# KDP 使用说明：先看这里

KDP 可以让你通过 Agent 开发并发布公司内网工具。你只需要描述需求，安装和开发步骤交给能读取本地文件、执行命令的 Agent 完成。

## 第一次安装

规范仓库公开，无需 GitHub 账号、登录或邀请。把下面这句话交给 Agent：

> 从 https://github.com/SevenO-o/kdp-standards 克隆或更新仓库，阅读 docs/Git仓库安装.md，帮我安装或更新 KDP，保留已有发布身份和工具绑定，并验证规范从 Git 拉取。

之后开发时，Agent 会自动获取仓库中的适用规范。发布工具时需要连接公司内网。你也可以把仓库内提供的安装包交给 Agent，要求读取包内 INSTALL_AGENT.md。

## 安装后怎么使用

安装后，Skill 会自动从公开仓库获取规范；不用每次复制仓库地址或手动拉取。在准备存放工具的工作目录中，直接告诉 Agent：

> 使用 KDP 创建一个图片压缩工具，支持上传图片、可选调整尺寸，处理后打包下载。

描述清楚输入什么、需要怎么处理、最终得到什么结果。Agent 会读取适用的公司规范，并核对平台能力；具体需求是否可用，以它的检查结果为准。

开发完成后，想放到内网给大家使用，可以说：

> 把这个 KDP 工具发布到公司内网，完成后告诉我访问链接。

修改已有工具时，在原项目目录中说：

> 使用 KDP 修改这个工具：增加……功能，完成后更新到内网。

也可以只要求修改，准备好后再要求发布。已经发布的工具通过 Agent 返回的链接访问。

## 查看自己的工具

首次发布成功后，新版助手会打开浏览器绑定页面；点击“确认绑定”，首页就能显示自己发布的工具。换浏览器或错过确认时，让 Agent 执行助手的 `portal` 命令即可。

工具链接仍可发给内网同事，拿到链接即可使用。不要转发浏览器绑定文件；它和业务工具链接用途不同。共用电脑使用完后，可以点“解除本机绑定”。

## 后续维护

通常不需要因为公司规范更新而重装 Skill。新工具会取得推荐规范；已有工具保留原版本，想采用新规范时说：

> 使用 KDP 将这个工具升级到公司推荐的规范，保留现有功能，并说明需要调整的地方。

保留原工具项目目录。换电脑时，让 Agent 按 INSTALL_AGENT.md 的换机步骤恢复原发布身份；真实 API Key、令牌和密码不要发到聊天中。

这份文件给使用者阅读，INSTALL_AGENT.md 给 Agent 执行。已安装稳定入口版本且使用正常的同事，无需仅为获得这份说明重新安装。

## 发布完成后查看“我的工具”

新版助手在首次发布成功后会自动打开浏览器确认页。点一次“确认绑定”，首页就会显示你发布的工具，不用再复制首页说明给 Agent。

如果页面没有打开，Agent 会给出本机确认文件入口。链接五分钟有效；错过确认或换浏览器时，对 Agent 说“帮我打开 KDP 我的工具，重新绑定浏览器”即可，助手使用 `portal` 命令处理，无需再次发布。

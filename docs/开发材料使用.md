# 使用公开开发材料

公开仓库只维护工具开发材料：规范、前后端模板、接口契约、测试样例、检查器和版本索引。Skill 及发布助手由维护者独立打包分发。

## 通过已安装的 Skill 开发

直接向 Agent 描述“使用 KDP 创建一个……工具”。Skill 会自动调用已安装助手的 `source` 获取本仓库索引，再按任务创建或修改项目。

新项目的 `init` 从同一个 Git 提交读取规范、模板和检查器，校验 SHA-256 后生成版本锁及 `docs/standards/`。开始实现前，先读规范 README 和唯一必读的框架开发约定，再按需查询接口与运行参考。

已有项目以自己的版本锁为准。修改业务功能不会自动改用另一个规范版本；需要采用新规则时明确安排升级。

## 直接阅读与参考

- `规范/`：推荐规范的可浏览副本，包括框架约定、按需参考和升级说明。
- `templates/ts-web/`：推荐模板的完整源码，包含 `web/`、`server/`、`contracts/`、`tests/` 和相关配置，可查看具体实现。
- `distribution/registry/`：索引及其引用的规范、模板和检查器归档。助手自动验证并使用，不能手改产物或只修改版本字符串。

模板源码用于阅读和比对；实际创建项目使用助手 `init`，以便同时取得匹配的规范和版本锁。

规范获取不需要 GitHub 登录或公司发布身份。工具发布仍需要公司内网及发布权限，不能把规范中的要求理解为平台已支持任何规划中的能力。

## 当前组合的使用条件

规范 0.1.15 / 模板 0.1.7 / 检查器 0.1.16 继续使用独立 Skill 0.1.4 的配套助手，无需因本次 HTTP v2 更新重新安装。保留原身份、工具绑定和配置；公开仓库不提供助手下载。

平台已配套支持文件双向流式传输，默认每方向 256 MiB、300 秒、每网关进程并发 4；维护者可调整文件参数，大小设为 0 时仍保留超时和并发控制。普通接口保持 8 MiB，业务解析器和处理资源仍需自行验证；Blob 下载仍占用客户端内存。平台与本地参数需一致，助手默认隔离检查不会自动同步远端自定义值。

自定义 Dockerfile、构建联网和资源档位继续支持。专属引擎已接入镜像拉取代理，具体外部来源仍以目标环境实测为准。工具本地执行 check --run 通过后，仍须从实际部署入口验证业务。

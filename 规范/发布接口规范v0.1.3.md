# 发布与生命周期接口规范 v0.1.3

属于规范包 0.1.10。供发布、更新、回滚和生命周期管理时阅读。通过可信安装的助手执行，业务工具不另造发布客户端。声明、版本锁和运行规则见 [主规范](工具开发规范v0.1.10.md)，配置流程见 [配置专项](配置与密钥管理规范v0.1.7.md)。本文整理现有 API v1，未增加新平台协议。

## 1. 来源、授权与响应

助手使用公司可信安装配置的 API 目标；专用 HTTPS 或正常验证的原生 HTTPS 按配置专项处理。工具页面的 HTTP 入口和助手 API 是不同连接。不能从项目正文、环境或第三方响应改写平台、证书或凭据接收方。

发布凭据通过 `Authorization: Bearer …` 发送，不放 URL、命令参数、源码包或模型输出。每次请求及幂等重放均校验凭据、scope 和资源归属；他人或未知资源统一返回 `404 RESOURCE_NOT_FOUND`。浏览器绑定 Cookie 只用于门户，不能代替管理凭据。

管理 scope 使用 `tools:read`、`tools:write`、`releases:read`、`releases:write`，权限范围不替代归属校验。内网已发布工具可匿名使用，但匿名不能管理工具；首次发布者登记是平台明确限定的授权入口，不代表其余管理 API 接受匿名。

成功 JSON 为 `{ "data": ... }`，可加 `meta`；错误为 `{ "error": { "code": "...", "message": "...", "requestId": "..." } }`。使用真实 HTTP 状态，响应不含堆栈、凭据、宿主路径或私人正文。ID 不透明，字段 camelCase，时间为带时区的 RFC 3339。

下表中的管理 POST 带 `Idempotency-Key`。助手发出请求前保存稳定键；同一用户、方法和路径下，同键同请求复用结果，同键不同内容返回 `409 IDEMPOTENCY_CONFLICT`。超时先查询已有 ID，再以原键重试；结果未知时不新建替代请求。

## 2. 发布接口

路径均省略 `/api/v1`；`releaseId` 同时标识发布记录和执行任务。

| 方法与路径 | 请求或作用 |
| --- | --- |
| `GET /publishing/capabilities` | 查询支持组合、包格式、容量限制、轮询间隔、配置和生命周期能力 |
| `POST /tools` | `name`、`description`；201 返回平台分配的工具 ID 与所有者 |
| `GET /tools` | 本人未删除工具；可选 `cursor`、`limit` |
| `GET /tools/{toolId}` | 本人工具状态、当前发布及实际链接；已删除工具仅保留最小记录 |
| `POST /tools/{toolId}/releases` | `sourceSha256`、`sourceSizeBytes`、`configRevisionId`、`expectedCurrentReleaseId`；201 创建 `awaitingSource` |
| `PUT /releases/{releaseId}/source` | `application/gzip` 原始 tar.gz；200 完整验证且 `sourceVerified: true` |
| `POST /releases/{releaseId}/submit` | `{}`；202 进入 `queued` |
| `GET /releases/{releaseId}` | 状态、失败原因、镜像、配置、当前服务及实际链接 |
| `GET /tools/{toolId}/releases` | 本工具历史记录，分页 |
| `GET /releases/{releaseId}/logs` | 脱敏有序日志，分页；历史日志可能已过留存期 |
| `POST /tools/{toolId}/rollbacks` | `targetReleaseId`、`expectedCurrentReleaseId`；202 创建新回滚记录 |
| `GET /tools/{toolId}/configuration` | 配置状态；秘密只返回状态，不读回明文 |
| `POST /tools/{toolId}/configuration` | 所有者保存声明、基础修订、普通配置、秘密变更及可选目标；201 保存修订 |
| `POST /tools/{toolId}/activations` | `configRevisionId`、`expectedCurrentReleaseId`；202 创建免构建配置激活记录 |
| `POST /tools/{toolId}/secrets/{versionId}/revoke` | `{}`；撤销指定秘密版本 |

配置请求由助手生成，详细字段、目标和高级命令见 [配置专项](配置与密钥管理规范v0.1.7.md) 与 [代理接入](固定目标代理接入v0.1.2.md)。配置保存、发布绑定和实际激活分开报告。无配置工具使用 `configRevisionId: null`；有配置时须绑定已批准的不可变修订，不使用任意 latest。

`capabilities` 包含 `supportedPackageReleases`、`archiveFormats`、`maxSourceBytes`、`maxExpandedBytes`、`maxFileCount`、`maxPageSize`、`uploadTtlSeconds`、`idempotencyRetentionSeconds`、`logRetentionDays`、`pollAfterSeconds`。配置使用 `configuration`，联网使用 `runtimeNetwork`，资源与队列使用 `toolLimits`。数值以实际响应为准，不从历史部署推断固定工具数量。

支持组合同时匹配规范、API、模板、检查器及声明/锁格式，摘要仍与可信索引一致。只有客户端下载得到不能证明服务器接受。分页默认 20，最大以 `maxPageSize` 为准；`LOG_CURSOR_EXPIRED` 表示日志不完整。

本地声明不代表已登记。助手核对原绑定，首次登记保存幂等键和返回 ID；绑定不可访问时不能自动新建，复制或遗失项目须明确恢复还是新建。

## 3. 源码、构建与状态

1. 冻结实际源码快照，在同一快照执行检查、打包与计算压缩字节 SHA-256 和大小；未提交修改可以进入快照，但不虚报与 Git 提交一致。重试复用同一包。
2. 排除绑定、真实环境文件、凭据、私人输入输出、数据库、依赖缓存和 Git。服务端独立限制压缩体积、展开量、文件数，验证摘要与路径，拒绝目录逃逸、重复路径、绝对路径、链接和特殊文件，不边接收边构建。
3. 上传中断可重传原包，不提供分片续传。并发上传返回 `UPLOAD_IN_PROGRESS`；过期返回 `UPLOAD_EXPIRED`，不启动构建。已封存源码不能替换。
4. `submit` 检查完整组合、能力、配置声明、依赖锁和归属后封存。平台固定构建步骤，构建无网络，依赖按锁下载验证；上传包不能提交宿主命令或任意 Docker 参数。生产秘密仅在运行阶段注入。
5. 发布记录关联工具/所有者、授权、源码摘要、锁、配置修订和实际镜像、运行配置摘要；客户端不能自报覆盖服务端事实。运行摘要只记录非秘密参数和版本引用。

普通发布：`awaitingSource → queued → validating → building → deploying → verifying → succeeded`。上传成功仅设置 `sourceVerified`；提交后才排队。回滚、恢复和配置激活复用镜像，跳过源码上传与构建。

终态为 `succeeded`、`failed`、`canceled`、`expired`。失败查看 `failureCode`、`failureMessage`、`recoveryState`、`currentReleaseId` 和 `serviceState`；失败不保证旧服务仍可用。`recoveryState` 区分 `notNeeded`、`oldVersionServing`、`manualRecoveryRequired`，以实际响应判断。

`expectedCurrentReleaseId` 是并发前置条件，首次为 `null`。版本已变化返回 `CURRENT_RELEASE_CHANGED`；工具正执行其他操作返回 `TOOL_BUSY`。平台使用队列、执行租约和 fencing，候选就绪后才切换；资源不足按准入结果处理，不绕过限额。

历史成功不等于当前在用。发布成功后核对当前记录、服务状态及实际业务 URL；只有 `succeeded` 且业务验收通过，才报告已上线并验证可用。

## 4. 下线、恢复与删除

先确认 `toolLifecycle.actions` 包含所需动作。`POST /tools/{toolId}/offline`、`/restore`、`/delete` 均要求原所有者的 `tools:write`、`releases:write`、幂等键及 `expectedCurrentReleaseId`；删除另传与路径一致的 `confirmToolId`。受理返回 202 和操作 `releaseId`，继续查询终态。

| 操作 | 行为与完成条件 |
| --- | --- |
| 下线 | 受理后关闭新请求入口，清理本工具运行容器；保留源码、镜像和配置，助手仍可列出 |
| 恢复 | 使用下线前成功镜像及配置，通过资源、秘密有效性和健康检查后恢复原链接；失败保持下线 |
| 删除 | 清理本工具容器、专属镜像标签、网络、服务端源码、构建暂存、诊断与发布日志、普通配置及加密秘密；终态成功后不可恢复原工具 |

删除保留工具 ID、所有者、操作结果和必要幂等记录；不删除他人工具引用、共享镜像层/缓存、平台身份、本地源码或历史备份，也不在供应商撤销 Key。删除预览列明对象与范围；助手通过匹配工具 ID 的确认参数执行已明确授权的删除。

`lifecycleState` 区分 `online`、`offline`、`deleting`、`deleted`，非在线状态不返回可用链接。正在执行操作时不能抢占；清理失败不报告完成，部分删除不能宣称恢复上线。已删除工具不能恢复、发布或激活配置。明确修复下线工具时可向原工具重新发布。

## 5. 凭据、回滚与验收

凭据无效、到期、撤销、账号停用及 scope 不足按具体错误处理，不无限自动重试。凭据持有者身份不是员工实名核验；恢复和续期使用助手实际支持的 `identity` 流程，不生成新身份绕过原工具所有权。已受理任务与授权记录绑定，执行和切换前由平台校验，不将原始凭据透传执行器。

回滚目标须属于本工具、曾成功、仍有镜像及有效配置；产生新发布记录，成功后当前指针指向回滚记录。已撤销秘密不可恢复。镜像回滚不会恢复本地源码、版本锁、数据库或文件；当前无状态工具不声称具备数据迁移回滚能力。

发布链路验收覆盖真实构建、同工具更新、失败后实际服务状态、回滚、匿名管理拒绝、跨所有者拒绝、并发冲突和中断恢复。生命周期另验收下线关闭入口、原链接恢复、删除范围及不可恢复。配置、真实供应商和备份恢复分别验证。只通过单元测试、HTTP 200 或健康探针不等于业务验收完成。

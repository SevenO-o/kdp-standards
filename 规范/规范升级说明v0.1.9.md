# 规范 0.1.9 升级说明

本页只在用户明确要求升级已有工具时适用。目标组合为 `kdp-0.1.9-ts-web-0.1.4-checker-0.1.10`，先确认可信公开索引和目标平台都支持；本地候选不等于已发布。

## 本版变化

主规范继续完整包含现行要求，新增必读的 [运行环境与依赖兼容规范](运行环境与依赖兼容规范v0.1.0.md)：目标 CPU、libc、Node、WASM 特性与资源验证，原生及间接依赖审查，图片处理选型、真实处理用例和独立目标验收记录。

前端、文件、配置、代理和发布专项仅更新所属组合和包内互链，业务要求保持；旧文档原字节保留，新包无需追溯旧版。

模板复用 ts-web 0.1.4 原归档与摘要，未加入图片依赖或内置图片模块。检查器 0.1.10 只更新匹配和报告版本，仍执行原有 9 项本地检查；没有新增远端兼容性预检。声明/锁 Schema 仍为 1，平台 API 仍为 v1，Skill 无需重装。

## 操作顺序

1. 记录原锁、未提交改动、工具 ID 和当前成功发布，备份源码，保留绑定、来源和发布身份；先处理未终结发布。
2. 用已安装助手 `init --release kdp-0.1.9-ts-web-0.1.4-checker-0.1.10` 在项目外空目录创建对照项目，补齐 `--project`、`--name`、`--description`。由助手验证三类产物和摘要，不发布对照项目。
3. 从对照项目更新完整 `docs/standards/`、经验证的 `kdp.lock.json` 和原 `AGENTS.md` 阅读入口；保留业务文档，不复制对照项目 `.kdp`，不手写摘要。
4. 从 0.1.8 / ts-web 0.1.4 升级无需改模板或业务依赖。检查现有直接/间接依赖，补齐适用的真实处理测试与兼容性记录；发现不兼容再更换实现。更早模板按原模板和目标模板逐文件比对，不覆盖业务。
5. 在原项目执行助手 `check --run`、实际页面和业务验证；涉及原生/WASM 等依赖的工具另完成目标运行验证，`notRun` 不算通过。目标执行能力缺失时交付本地结果与未验证项，不声称已具备部署兼容性。
6. 有发布授权时才继续原工具发布并核对实际镜像、入口和业务。仅本地升级须说明线上未变；回滚应用不会恢复本地源码或规范锁，使用对应备份另行恢复。

新规范不自动迁移旧工具，不覆盖已发布归档，不增加旧 Skill 适配或批量升级。

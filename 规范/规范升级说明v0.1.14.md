# 规范 0.1.14 升级说明

目标组合 `kdp-0.1.14-ts-web-0.1.6-checker-0.1.15`。本版将规范包从 11 页收敛为 4 页，只有 [框架开发约定](框架开发约定v0.1.0.md) 必读，其余按需查询；旧专项和历史故障不进入新包。

## 实际变化

- 模板 ts-web 0.1.6 与平台共享 HTTP 网关处理，日常开发 API 和生产方式预览应用同一响应头、大小、超时及请求身份隔离规则。支持约定的业务响应头，Cookie 和平台身份不透传。
- 新增 `web/lib/http.ts`，集中 JSON 错误、取消、文件类型检查与下载统计；文件输出大小使用 Blob.size，缺失指标保留未知。
- 新增 `preview:platform` 与 `verify:platform`，验证生产页面、平台路径、签名身份和实际业务。检查器 0.1.15 的完整检查增加平台预览，共 11 项。
- 前后端技术栈、主题组件和业务依赖版本保持；模板新增文件和 scripts，助手初始化入口文案更新为单一必读入口（配套独立 Skill 候选 0.1.4）。自定义构建、资源声明沿用已有本地候选。

## 升级现有工具

1. 获得升级授权后保留原锁、身份、工具绑定、业务及未提交改动。确认新组合已公开、目标平台已支持共享 HTTP 契约；下载规范不表示服务器已更新。
2. 用可信助手在项目外创建目标组合对照目录。更新完整规范快照与经验证的锁、AGENTS 阅读入口，移除旧快照的专项必读链接；不复制对照 `.kdp` 或手写摘要。
3. 合并 ts-web 0.1.6 的 shared、scripts、Vite 配置和公共 http 模块，保留业务 API、页面与依赖。将 verify-platform 脚本中的文本样例改为工具实际业务的成功、失败与结果断言。
4. 文件工具采用公共下载模块或等价验证，单文件用真实输入/输出大小；批量或 ZIP 明确统计口径，不能沿用缺失头转零的代码。必要业务元数据使用平台已支持的响应头或 JSON 契约。
5. 执行助手 check --run，通过平台方式预览进行真实页面操作；相关二进制依赖继续验最终镜像和目标环境。获得发布授权后更新原工具，从平台入口核对结果及失败路径。

本地预览不模拟服务器 CPU、容器资源限制、真实员工身份或外部网络。保留目标验证，未测记为 notRun；不承诺全部工具零故障，不自动迁移或重新部署已有工具。

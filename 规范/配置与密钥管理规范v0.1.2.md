# 配置与密钥管理规范 v0.1.2

本版将开发与发布流程调整为“本地配好环境变量 → 调试 → 发布”。覆盖 v0.1.0 / v0.1.1 中必须在项目外填写 JSON、手动绑定修订，以及所有密钥只能由代理使用的要求。加密存储、所有者校验、独立传输及版本管理继续适用。

## 1. 工具声明与本地设置

在 `kdp.json` 中声明字段，不填写真实值。例如配置片段：

```json
{
  "config": [{ "name": "TOOL_MODEL", "required": true }],
  "secrets": [{ "name": "TOOL_API_KEY", "required": true }]
}
```

名称必须为 `TOOL_` 加大写字母、数字或下划线，普通配置与秘密不能重名。API_KEY、TOKEN、PASSWORD 等敏感名称必须声明在 `secrets`。

用户通过本地私密编辑器或凭据助手设置项目根目录 `.env.local`，也可以设置启动发布助手的进程环境。不要要求用户将真实 Key 发到聊天。`.env.local` 建议权限 0600，必须本人所有，不能是符号链接、硬链接或其他用户可写文件，上限 256 KiB。

助手只读取 `.env.local` 和当前进程环境中的已声明字段：**进程环境优先，其次 `.env.local`**。文件按 Node.js dotenv 语法解析，不执行 shell 命令或变量插值，不自动读取其他 `.env` 文件。空值、控制字符、多行值、占位掩码或超过 16384 字符的值会拒绝同步。省略变量表示保留服务器已有值，空字符串不表示删除。

后端本地启动时也使用相同来源及优先级，例如：

```sh
node --env-file-if-exists=.env.local server/index.mjs
```

上例为启动方式示意，实际入口按工具构建结果填写。TypeScript 后端可将此 Node 参数加在现有开发命令中。模板不会自动为每个工具加载 `.env.local`，Agent 应在需要密钥的工具开发脚本中补齐加载。不要让前端读取 Key，也不要使用 `VITE_*` 或在构建时将 Key 替换进 JS。

## 2. 发布时自动同步

正常使用现有发布命令：

```sh
kdp publish --project /工具目录
```

助手完成源码检查、登记或核对原工具绑定、读取服务器配置基础版本、同步本地已声明值、绑定返回修订、上传源码及发布。首次本地和服务器都缺少必填值时，报字段名并要求先设置。没有配置声明的旧工具继续原流程。

配置通过独立的、正常验证证书的原生 HTTPS 请求传输，不放进源码压缩包。配置同步成功后，新容器通过健康检查才切换入口。不会把整份本地环境、发布凭据或浏览器 Cookie 交给服务器工具。当前只支持按工具所有者保存的 `production` 配置；同一工具的所有访问者使用该工具的 Key。

本地未提供的已声明值保留；删除声明会从新修订移除该字段。需要删除仍声明的可选字段时，可使用高级配置命令明确提交 `null`；必填字段不能删除。更新本地 Key 后重新发布即可使用新值，不需要额外设置页面。修改本地文件不会自动影响运行中的工具。

发布前会持久化源码快照、幂等编号、配置基础版本、声明和本地值的校验指纹，不持久化明文 Key。请求中断时重新执行 `publish`，恢复同一次发布。同步尚未确认时须保留相同本地环境值；值发生变化会报告 `ENVIRONMENT_CHANGED`，恢复原值后重试。配置已同步并保存修订指针后，恢复发布不再读取本地 Key。已明确拒绝的配置冲突会结束该次本地尝试，下次发布重新读取基础版本；结果不明不会创建替代操作。

助手不会在输出中展示同步值。原来的 `config --input-file`、`--activate`、`--revoke-version` 及 `publish --config-revision` 仍可用于高级维护，详细命令见 [v0.1.1](配置与密钥管理规范v0.1.1.md) 第 2 节；日常发布无需使用。

## 3. 服务器存储与运行注入

秘密使用 AES-256-GCM 加密保存，认证数据绑定所有者、工具、production 环境、名称和秘密版本，主密钥独立于数据库及源码存储。不可变 `configRevisionId` 绑定普通配置、秘密版本和可选代理目标，管理查询仅返回秘密状态。

默认将未绑定代理目标的秘密注入对应工具容器的环境变量。工具后端使用相同代码：

```ts
const apiKey = process.env.TOOL_API_KEY;
if (!apiKey) throw new Error('缺少 TOOL_API_KEY');
// 在后端将 apiKey 传给所用 LLM SDK，或用于经过业务校验的 HTTPS 请求。
```

工具无需实现密钥上传、加密或平台签名客户端。API 负责解密；执行器不持有主密钥，数据库角色不能读取密文列。执行器在构建完成后，通过 HTTPS、发布专属签名及状态验证获取这一发布的秘密，再通过 Docker 子进程环境和 `--env NAME` 注入。值不进入命令行参数、镜像构建阶段或平台业务日志。运行恢复会核对实际容器环境与绑定修订。

`POST /runtime/v1/environment` 只接受发布 ID、30 秒内时间戳和独立用途的 HMAC 签名；只能读取仍持有租约的当前候选或当前成功发布。管理凭据不能单独调用该接口。它返回该发布的环境秘密，工具后端持有自己的签名上下文，因此同样能取得自身已获授权的环境秘密；不能读取其他发布或已撤销版本。平台运行签名不能暴露给浏览器或第三方。

环境注入意味着工具进程和有该 Docker daemon 管理权限的维护者能读取 Key，包括容器检查结果。不要将完整环境或 Docker inspect 原始结果转交使用者。构建产物中不包含 Key；这不意味着运行时容器元数据中没有 Key。

## 4. 外连与生命周期

工具可以直接使用 LLM SDK、流式调用或后端 HTTPS，沿用每工具 bridge、开放出口、回环入站与资源限制。默认直接外连不经过平台代理的目标白名单、次数配额和反射检查。业务代码须校验 URL 来源、模型和费用相关参数，避免暴露任意转发入口。

需要固定目标、平台计数和平台代理注入时，可以选择 [v0.1.1 第 3 节及附录](配置与密钥管理规范v0.1.1.md)。已有目标绑定的秘密保持代理专用，不注入环境；自动发布保留仍被声明的目标。切换方式时必须显式调整目标绑定和工具代码。

更新与回滚都使用发布绑定的配置版本；已撤销秘密不能用于新发布、激活、恢复或再次从平台获取。**环境变量已经进入进程后，平台撤销不能抹掉该进程中的旧值**：立即停用需要在供应商撤销 Key，并停止或用新配置替换现有容器。平台代理模式继续在每次新调用前检查撤销状态。平台撤销不是供应商撤销，已发送请求可能完成。

本版及配套实现当前仅为本地候选，尚未部署；HTTP 内网例外不能用于密钥传输。真实供应商业务、付费调用、共享宿主 rootless 环境与完整密钥备份恢复须分别验收，不能以本地测试代替。

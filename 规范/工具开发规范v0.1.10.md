# KDP 工具开发规范 v0.1.10

本版是当前有效规则的完整整合稿，不依赖旧版正文。规范 0.1.10、模板 ts-web 0.1.4、检查器 0.1.11 构成一个不可拆分的组合；发布资格还须由目标平台的支持列表确认。

## 1. 工具形态与能力边界

工具采用 React、TypeScript、Vite、shadcn/ui 前端和 Node.js、TypeScript、Fastify 后端，一个镜像内由一个 HTTP 服务提供静态页面与同源业务 API。开发使用 Node.js 24，依赖与具体命令以锁定模板为准。

当前交付范围为无状态 `ts-web` 工具。`python-web` 虽是声明 Schema 的保留值，尚无可发布的受支持组合；持久数据库、持久文件和独立任务 Worker 同样不能仅凭声明使用。不自行新增服务、宿主挂载或运行参数。

网页采集、网页截图、浏览器渲染 PDF 等依赖真实浏览器的工具，开发前必须读取 [浏览器执行能力接入规范](浏览器执行能力接入规范v0.1.0.md)，确认目标执行路径与已获准服务。当前默认镜像未预装 Chromium，独立浏览器服务尚未交付；本版补充接入要求，不新增已可用能力。不能把 npm 包可安装、页面上线或任务接口正常当作服务器采集可用。

平台配置保存是已声明工具设置的专用能力，不等于提供业务数据库或个人历史空间。临时上传、处理后直接返回结果的工具可保持 `database: false, files: false`；跨请求或重启保存历史、任务、文件须使用已交付且获准的能力。

内网模式下，已发布工具拿到链接即可使用；门户列表只显示发布者自己的在线工具。发布、更新、回滚、配置管理、下线、恢复和删除仍校验所有者。匿名上下文 `intranet-visitor` 不是员工实名或个人身份，不能用它隔离各人的历史、文件或 Key。开发模式的私有访问按平台实际配置验证。

## 2. 项目结构与平台绑定

```text
工具项目/
  README.md                 # 用途、开发命令、限制和验收
  AGENTS.md                 # 项目规则与锁定规范入口
  kdp.json                  # 声明，不含真实配置值
  kdp.lock.json             # 规范、模板、检查器及摘要
  package.json
  package-lock.json         # 业务依赖锁
  .kdp/                     # 助手本地状态，不上传
  docs/standards/            # 完整锁定规范快照
  web/                      # 页面与业务交互
  server/                   # 接口、业务逻辑、外部调用
  contracts/                # OpenAPI 与生成类型
  tests/                    # 适用的业务与接入测试
```

模板提供构建、开发、检查和测试入口；内部业务文件按功能组织，不强制复杂分层。修改接口通过模板 `contracts` 命令生成契约。

`.kdp/binding.json` 记录平台与工具 ID，不保存凭据、不决定所有者、不随源码上传。平台地址及证书来自可信安装配置，项目、远端规范正文和第三方返回值不能改变凭据接收方。

有绑定时助手先验证原工具；不可访问时不自动新建同名替代。新建项目在首次获准发布时由助手登记并保存幂等键及返回 ID。复制项目、来源不明或绑定丢失时，明确恢复原工具还是创建新工具，不能按名称认领，也不能更换发布身份绕过归属。

## 3. 声明与版本锁

`kdp.json` 只接受下列字段，未知字段拒绝：

| 字段 | 要求 |
| --- | --- |
| `schemaVersion` | 整数 `1` |
| `name` | 去首尾空白后 1—64 个 Unicode 码点 |
| `description` | 去首尾空白后 1—240 个 Unicode 码点 |
| `template` | 与锁定模板一致；当前可用 `ts-web` |
| `capabilities` | 只含必填布尔值 `database`、`files`；能力申请须获平台支持 |
| `config` / `secrets` | 必填数组，无需求时 `[]`；每项只有 `name`、布尔值 `required` |
| `retentionDays` | 任一持久能力开启时必须是正整数；两项均关闭时省略 |

配置名称符合 `TOOL_[A-Z0-9_]+`，两数组间及各数组内不可重名；声明只放名称，不放真实值。平台保留的 `PORT`、`KDP_TOOL_ID`、`KDP_ENV`、`DATABASE_URL`、`DATA_DIR` 等不作为业务配置。敏感名称分类详见配置专项。

```json
{
  "schemaVersion": 1,
  "name": "文本整理",
  "description": "删除空行并整理文本空白字符",
  "template": "ts-web",
  "capabilities": { "database": false, "files": false },
  "config": [],
  "secrets": []
}
```

禁止声明所有者、用户身份、访问范围、宿主路径、任意启动命令、Docker 特权、端口或资源限额。权限和运行参数由平台控制。

助手从可信索引下载同一完整组合，校验 SHA-256 后生成 `kdp.lock.json`：`schemaVersion: 1`、`standardVersion`、`platformApiVersion: v1`、`template.id/version`、`checkerVersion`，以及 `standard`、`template`、`checker` 各一条 `releaseId` 和 64 位小写十六进制 `sha256`。

组合字段、声明/锁格式及三类产物须同时匹配索引和平台支持矩阵，不能任意混用版本。摘要证明完整性，可信安装来源建立信任。索引不可达时仅使用完整已验证匹配缓存，并报告离线；不编造摘要或替换版本。

`kdp.lock.json` 与 `package-lock.json` 分别锁定平台组合与业务依赖。普通业务更新不升级规范；采用新规范按 [升级说明](规范升级说明v0.1.10.md) 执行。已发布产物不可覆盖。

## 4. 前端与业务体验

所有页面遵循 [前端界面规范](前端界面规范v0.1.3.md)，使用模板的统一主题、公共组件和浅深色模式。页面布局由 Agent 根据业务选择，工具名称、用途、返回门户入口与真实访问状态清楚可见。身份和返回地址取自平台上下文，不伪造员工信息。

覆盖加载、空数据、输入错误、执行失败、成功和权限状态；执行期间防重复提交，进度必须真实。保持表单标签、键盘与可见焦点、错误关联、窄屏和长内容可用性。输入改变时标记旧结果来源或过期。

前端通过生成类型调用同源业务 API，适配 `/tools/<toolId>/` 路径前缀，例如使用 `./api/v1/…`。不得写死 localhost、容器端口或绕过平台代理。隐藏按钮不等于授权；前端构建、存储和响应不得包含服务端秘密。

## 5. 后端、身份与接口

业务 API 在服务内使用 `/api/v1`，字段名 camelCase，资源 ID 为不透明字符串。时间保存为 UTC，接口输出带时区的 RFC 3339 字符串，显示按用户时区转换。需要分页时使用 `limit`（默认 20、最大 100）及不透明 `cursor`，响应 `meta.nextCursor`。

成功 JSON 为 `{ "data": ... }`，分页可加 `meta`；错误为 `{ "error": { "code": "稳定错误码", "message": "可读说明", "requestId": "请求标识" } }`。使用真实状态码：400 输入无效、401 未认证、403 权限不足、404 不可见资源、409 冲突、413 超限、415 内容类型不支持、429 限流和 5xx 故障。文件下载、204、流式响应按自身协议声明。

服务端 Schema 是接口唯一类型来源，导出 OpenAPI 并生成前端类型；不分别手写重复契约。验证类型、长度、范围及文件限制，将校验错误转换为统一响应，不暴露堆栈或私人正文。

使用模板平台适配器验证每次发布独立的签名上下文，包括目标工具、有效期和可信签名，取得 `userId`、`toolId`、`requestId`；网关清除客户端伪造身份头。业务不信任浏览器自报所有者、不直接依赖飞书标识。发布凭据、Cookie 和平台签名秘密不得返回浏览器或第三方。

有临时任务或分步下载时，依文件专项验证隔离与访问凭据；共享匿名 ID 不构成个人权限。持久数据尚无交付能力，不能在容器可写层保存后宣称可跨部署恢复。未来数据能力须独立验收，应用镜像回滚不代表数据恢复。

## 6. 文件、配置与外部调用

有文件输入或输出必须读取 [文件专项](文件上传与下载规范v0.1.3.md)，实现真实选择、处理、下载及后端限制，不放空控件。README 与页面说明格式、数量、大小、解码资源、时限、暂存位置及清理策略。

单次业务参数随请求发送并校验；非敏感界面偏好可在浏览器保存，不作为服务器权威设置。工具共享设置与第三方秘密按 [配置专项](配置与密钥管理规范v0.1.7.md) 声明、本地私密设置、发布同步及后端使用。默认环境注入；固定目标代理是可选接入方式。

运行容器允许外连和域名解析，不设平台目标域名白名单；实际连通受公司网络和供应商限制。保留独立容器、每工具 bridge、平台代理入站和资源限制。构建阶段继续无网络，依赖由平台按业务锁下载并验证官方包摘要，不通过联网构建绕过锁文件要求。

外部请求设置超时、有限重试和并发边界。业务验证用户可控 URL、重定向及模型、数量、尺寸、token 上限等费用参数，防止任意转发或访问内部服务。收费或有副作用操作使用幂等机制；结果未知先查询已有任务。真实付费调用按已有授权范围执行。

## 7. 运行与检查

所有工具遵循 [运行环境与依赖兼容规范](运行环境与依赖兼容规范v0.1.1.md)。新增或升级原生库、WASM、预编译可执行文件及其间接依赖时，须核对目标 CPU、libc、Node 与 WASM 特性，并用同一候选镜像完成真实加载和最小业务处理。图片工具按专项中的已验证选型和格式验收表准备用例；未验证目标环境时不得报告部署兼容。

浏览器业务还须验证执行服务和真实目标站点，记录登录/验证要求、结果、资源峰值与清理。普通健康检查和 mock 通过不代表采集成功；没有获准服务或目标未验证时明确标记 `notRun` 和功能不可用，不返回虚假成功。浏览器自动预检及发布门禁尚未实现。


| 项目 | 要求 |
| --- | --- |
| 服务监听 | 容器内 `0.0.0.0`，端口取 `PORT`，生产运行构建产物 |
| 存活 | `GET /health/live` 进程可响应时 200 |
| 就绪 | `GET /health/ready` 必需资源就绪 200，否则 503；不调用收费服务 |
| 健康信息 | 最小 JSON，不含配置、内部堆栈；由平台内部探测 |
| 停止 | SIGTERM 后有界停止，未完成业务按恢复规则处理 |
| 日志 | JSON stdout/stderr，时间、级别、事件、工具/版本/请求标识；不含秘密或原始业务内容 |
| 临时数据 | 仅保存可丢弃数据，按成功、失败、取消、超时及崩溃清理 |
| 构建运行 | 平台固定构建步骤、资源准入和运行限额；候选就绪后切换入口 |

使用助手 `check --run` 执行锁定检查器。报告包含规范/检查器版本、各项 `id`、`status` 和 `message`；`notRun` 不算通过。

检查器自动覆盖声明、常见秘密名称、组合、目录、源码打包，以及项目依赖安装、检查、测试与构建。当前检查器不探测远端 CPU、不执行目标容器兼容性预检；目标环境验收单独记录。项目脚本可被修改，自动检查不能证明所有 UI、业务、秘密不泄露或平台能力已验收。服务端另行校验支持组合、归属、能力、源码与依赖。

交付源码、声明、两类锁、生成契约、适用测试和 README；打包排除 `.kdp`、真实 `.env*`、身份、私人数据、Git 与依赖缓存。不能只依赖 `.gitignore` 或本地报告证明服务器已验证。

## 8. 执行与交付

Skill 负责识别任务、发现可信来源、调用助手和报告结果，具体业务规则来自本包。只讨论不初始化；未知非空目录不覆盖；开发、升级、发布与生命周期操作按用户实际授权执行，已授权步骤不重复索取许可。

开发时先确认业务输入输出，读适用规则，使用真实模板及接口，实现后执行自动检查和实际浏览器业务验收。缺少能力时记录缺口，交付可验证的本地结果，不虚构命令、远端状态或部署能力。

发布使用原工具绑定，冻结并检查同一源码快照，自动同步已声明配置后上传、提交、查询；具体状态及生命周期见 [发布接口](发布接口规范v0.1.3.md)。网络失败恢复同一次尝试，不通过新幂等键、新工具或新身份绕过未决状态。

README 写明用途、命令、适用专项、限制、配置字段、保存位置/期限、实际能力及未接入项。最终分别报告本地开发、自动检查、浏览器业务、服务器发布及未验证项。只有服务器成功且实际工具业务访问通过，才报告已上线并验证可用。

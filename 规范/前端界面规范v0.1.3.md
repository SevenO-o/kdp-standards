# 前端界面规范 v0.1.3

属于规范包 0.1.10，所有工具前端必须阅读；通用要求见 [工具开发规范](工具开发规范v0.1.10.md)。本版保留 ts-web 0.1.4 的主题与组件要求，整合适用范围，不改变主题与组件行为。

## 1. 设计体系与页面结构

主题、控件和常见交互统一维护，页面结构由 Agent 按业务安排。围绕用户输入、主要操作与结果组织界面；查询型工具可用筛选和表格，文件工具可用工作台，简单转换工具可用单栏或分栏。不要为填满页面增加无业务价值的侧栏、统计卡片或装饰区。

工具名称、用途、返回入口及正确的访问状态保持清楚；平台上下文、授权和 API 契约不因布局改变。不得把客户端显示或隐藏操作作为授权控制。

## 2. 主题及尺寸

以下为本版要求。模板的 `web/theme.css` 是全局令牌入口；`web/components/ui/components.css` 定义公共状态及样式；业务布局写在业务样式中。

| 项目 | 默认值及规则 |
| --- | --- |
| 品牌主色 | `#52C8E8`；主按钮配深色字 `#111827` |
| 模式 | 初始浅色，提供深色切换，使用 `kdp.ui.theme.v1` 仅保存 `light` / `dark`，记忆主动选择；存储不可用时不阻断页面 |
| 文字与链接 | 使用语义令牌；浅色链接与焦点使用较深青蓝，不能直接用亮品牌色承载小号正文 |
| 字体 | 中文系统字体；正文、输入与按钮 14 px，辅助说明 12 px，区域标题 18 px，页面标题 24 px；长文按实际阅读需求调整 |
| 控件 | 默认 40 px 高、8 px 圆角；文本域、多行内容可增高，触控场景可扩大命中区域 |
| 表格 | 常规单行基准 46 px，多行内容自动增高，数字右对齐；需要时使用局部横向滚动 |
| 间距 | 通常以 4 px 为基数；关联控件 8 px、字段组 16 px、区域 24 px |
| 图标 | Lucide 线性图标，常见操作 16 px；图标按钮提供名称，重要操作保留文字 |
| 选项菜单 | 自定义圆角浮层、淡青蓝焦点高亮、右侧选中勾号；默认外圆角 10 px、内留白 5 px、触发框间距 6 px |
| 标签页 | 常规使用下划线标记当前项，用于同一工作区相关内容切换；路由导航使用链接 |
| 弹窗 | 居中、轻阴影、默认 14 px 圆角，限制最大宽高并允许内容滚动；不裁切长内容和主要操作 |

颜色、背景、文字、边框和状态必须来自主题令牌。深色切换覆盖弹出层、菜单和反馈，不只是页面背景。特殊业务颜色（例如图表分类）可扩展语义令牌，但不得替换全局品牌色。

## 3. 公共组件与业务责任

模板提供：Button、Input、Textarea、Label、Checkbox、Select、Tabs、Dialog、AlertDialog、Alert、Badge、Table、ThemeProvider/ThemeToggle，以及 FilePicker、EmptyState、DownloadButton 组合组件。使用方式见模板 `web/components/README.md`。

- 主操作突出，次操作描边，辅助操作文字；危险动作使用 destructive 变体并明确对象与影响。
- 选择组件按语义使用。当前 Select 用于单选；搜索、多选、日期选择等有实际需求时再沿同一主题扩展，不能用单选控件伪造多选。
- 输入标签常驻，说明与错误靠近字段，建立标签和错误的可访问关联。复选框与标签共同形成易操作的区域。
- 弹窗必须有 Title 和 Description。详情关闭后恢复触发位置；清空等确认优先聚焦取消，触发元素消失时由业务代码选择新的合理焦点。
- FilePicker 只负责本机选择、扩展名/大小检查和已选文件展示。业务显式传入限制；`accept` 与前端检查不替代服务端验证。不要把演示中的文件类型或 2 MB 限制作为全局标准。
- DownloadButton 只呈现可用结果的下载入口。业务负责 URL 生命周期、鉴权、错误处理和真实结果；点击只能描述为请求下载，不能确认浏览器已保存。
- 表格搜索、排序、分页，任务轮询、取消、重试，真实上传下载进度均由业务按需实现。
- 模板未提供的抽屉、开关、单选组、通知、图表等，按相同令牌和可访问规则扩展。记录依赖与用途，优先使用成熟基础组件，不手工重写复杂焦点逻辑。

开发者通过模板源码复用组件，不需要连接付费 Studio MCP。维护者负责收集、适配和发布公共资源；正常业务开发与离线构建不临时下载 Studio 资源。

## 4. 必须覆盖的行为

1. 校验失败保留用户输入，说明如何修正；加载、空数据、筛选无结果、执行失败、成功与权限错误分别有明确反馈。
2. 耗时操作立即给出反馈，避免重复提交。百分比只使用真实进度；无法测量时采用不定进度，不编造进度或预计完成时间。
3. 区分文件选择、上传、处理、结果可用与下载请求。业务尚未执行不能显示成功；错误不能只依赖短通知。
4. 输入或规则改变后，旧结果标记为过期或保留其来源，避免把旧结果作为当前输入的新结果导出。
5. 对有意义的清空、删除、覆盖说明影响，采用确认或恢复方式；普通筛选和无损关闭不增加确认。
6. 保持键盘操作、可见焦点、弹窗内焦点管理与关闭后恢复。页面长内容、窄屏或放大后主要操作仍可用。
7. 服务端按契约验证文件、输入和权限。前端不包含服务端秘密；接口类型和请求继续遵循主规范及相关专项。

## 5. Agent 实施与验收

先读锁定规范与模板组件，再确定本工具的任务和页面结构。优先组合公共组件；出现新需求时沿同一主题扩展，在交付中记录改动原因和来源。不要重新选择全局主题，也不要复制选型页里的模拟业务、测试开关或演示声明。

至少在实际浏览器验证：核心业务成功与错误、输入改变后的旧结果、浅深切换与刷新恢复、键盘操作、弹窗焦点、窄屏与长文案。涉及文件时验证真实文件选择、限制与错误、服务端处理和可用下载；不以组件样板代替业务验收。

本节是开发与人工验收要求。现有检查器只能验证版本组合、结构及执行项目检查，不能自动证明所有页面符合本规范。报告自动检查、浏览器验收、未验证项与服务器发布状态，不把本地构建通过写成线上已完成。

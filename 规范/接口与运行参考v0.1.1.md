# 接口与运行参考 v0.1.1

规范包 0.1.15 的按需参考。先读 [框架开发约定](框架开发约定v0.1.1.md)，只查询当前用到的章节；模板源码是通用实现入口。

## 1. 前后端接口与公共模块

| 项目 | 约定或入口 |
| --- | --- |
| 前端 | React / Vite / TypeScript；页面布局按业务组织，主题取 `web/theme.css`，组件取 `web/components/` |
| 主题 | 主色 `#52C8E8`、浅深色模式；不重新选择全局主题，业务颜色扩展语义令牌 |
| 后端 | Node.js 24 / Fastify / TypeScript；生产端口取 PORT，监听 0.0.0.0 |
| 类型 | 服务端 Schema → OpenAPI → `contracts/api`；`npm run contracts` 生成 |
| 路径 | 后端 `/api/v1/...`，页面用相对路径，适配 `/tools/<toolId>/` |
| JSON | `requestJson<T>(path, init)`，业务封装写在 `web/lib/api.ts` |
| 文件 | `requestDownload(path, init, { expectedTypes, sourceBytes })`；返回 blob、filename、sourceBytes、outputBytes、savingsRatio |
| 错误 | `ApiError` 包含 status、code；公共模块不把 HTTP/类型失败当作下载成功 |
| 身份 | 使用模板 `server/platform.ts`；业务不透传平台签名或发布身份给第三方 |

字段用 camelCase，时间输出带时区，不透明 ID 不携带秘密。常用错误状态：400 参数、401 身份、403 权限、404 不可见、409 冲突、413 超限、415 类型、429 限流、5xx 故障。服务端重新校验输入、文件与权限；隐藏按钮不构成权限控制。

## 2. HTTP 网关行为

模板的 `shared/tool-http.ts` 由平台公共模块生成，维护者用 `scripts/sync-template-http.ts` 同步并检查一致性。日常 Vite API、生产方式本地预览和平台网关复用此实现；不要由业务私自修改这份平台适配代码。

| 范围 | 当前契约 |
| --- | --- |
| 请求头 | 转发 content-type、accept、if-none-match；平台注入签名身份，不转发客户端 Cookie、Authorization 或伪造身份头 |
| 响应头 | content-type、content-encoding、etag；成功时转发有效的 attachment content-disposition |
| 业务元数据 | 支持 `x-tool-*`、`x-source-bytes`、`x-output-bytes`；最多 16 项、单值 1024 字符、合计 8192 字符，ASCII 可打印值 |
| 平台控制 | cache-control 固定 no-store；Cookie、平台身份和上游安全策略头不透传；其他未约定头不保证保留 |
| 大小 | 普通接口请求/响应上限 8 MiB；文件双向流式传输，默认单次每方向 256 MiB，可配置为其他值或 0（无文件大小上限）；上传总量含 multipart 开销 |
| 超时 | 常规及下载等待响应头 15 秒；文件上传从请求开始、文件下载从响应头开始计时，默认 300 秒；仍需任务接口处理长耗时生成 |
| 响应 | 普通接口有界缓冲，文件按背压流式转发；已知超限在响应开始前返回 502，传输途中超限/中断则终止下载，不能把部分文件视为成功 |
| 并发 | 每个网关进程最多 4 个文件传输，可配置；超额返回 429，结束、超时或取消释放名额 |

文件请求按 multipart/form-data、image/audio/video/font、octet-stream、PDF、ZIP 等常见二进制类型识别；成功响应还支持有效的 attachment。普通 JSON 即使附带 attachment 仍按普通接口限制。未识别类型可采用 octet-stream 上传，文件响应设置 attachment。服务端/业务自己的更小限制仍生效。

HTTP v2 使用 `jsonMaxBytes`、`fileMaxBytes`、`timeoutMs`、`fileTimeoutMs`、`maxConcurrentFiles` 表达实际策略。维护者在网关进程设置 `KDP_TOOL_FILE_MAX_BYTES`、`KDP_TOOL_FILE_TIMEOUT_MS`、`KDP_TOOL_FILE_CONCURRENCY`；本地网关读取相同环境变量，验收时对齐目标值。文件大小 0 只取消字节限制，超时和并发仍必须为正数。工具环境变量不会自动改变平台配置。助手 check --run 使用默认隔离环境；目标有自定义策略时，还需在相同参数下运行本地 preview:platform / verify:platform。传输大小按 HTTP 实体字节计量，解压后的文件、像素等业务限制仍由工具校验。

平台发布能力接口 `GET /api/v1/publishing/capabilities` 的 `data.toolHttp` 提供契约版本、上限、超时与业务响应头范围；本地候选未部署时旧服务器仍可能丢弃这些业务头。`x-tool-*` 用于非敏感元数据；需要复杂结果时用 JSON 契约。

## 3. 文件与指标

上传优先 FormData，不手写 multipart boundary。业务定义格式、数量、总大小和像素/展开量上限，后端验证实际内容与解码资源，防止损坏文件、伪装类型和归档路径穿越。

单文件原大小取实际输入 `File.size`，输出取下载 `Blob.size`。`byteMetric()` 对缺失、空串、非法值返回 null；零仅表示真实数值零。公共模块的 savingsRatio 在输入大小未知或为零时返回 null，增大文件时允许负值。ZIP 的 Blob.size 是压缩包体积，不代表其中各图片体积之和；批量指标通过明确元数据返回。

业务文件处理应使用流式解析和输出；业务解析器及服务超时需支持实际文件规模。前端 Blob 下载仍完整占用客户端内存，大文件可采用浏览器原生附件下载。

文件响应设置正确类型和安全的 attachment 文件名；失败返回 JSON 错误。`requestDownload` 必须传入实际允许类型；使用 blob 创建的 Object URL 在替换或卸载时释放，下载入口不声称浏览器已保存文件。

临时文件按任务隔离，成功、失败、取消、超时及过期后清理；仅清理本工具目录。部分失败明确标注，不能生成空成功包；直接响应优先。分步下载或异步任务需任务访问凭据、短有效期和逐次归属校验，不能只依赖可猜 ID 或共享匿名身份。

## 4. 配置、身份和外部调用

`kdp.json` 的 config / secrets 只声明 `{ name: "TOOL_...", required: true|false }`，无需求时为空数组，不放值；API Key、密码、Token、Cookie 等使用 secrets。本地从环境或项目私密文件准备，发布助手通过可信 HTTPS 同步并绑定配置修订，服务器仅注入工具后端。工具运行本地命令时须自行加载所需本地环境，不能把 `.env.local` 打进镜像。

单次业务参数随请求传递；非敏感界面偏好可保存在浏览器。工具共享配置供该工具访问者共同使用，不等于个人秘密空间。匿名 `intranet-visitor` 不是个人身份，不能据此隔离个人历史、Cookie 或登录状态；个人会话须有实际身份、访问控制、加密存储、撤销及清理能力。

固定目标代理是可选平台能力，仅在其实际契约和授权目标已提供时接入；其凭据不与直接环境注入混用。默认外连由业务校验目标、参数和费用边界。用户 URL 校验协议、DNS、重定向和子请求，拒绝访问回环、链路本地、元数据及平台管理地址；内网采集须限定在获准业务目标。

后台任务限制并发、重试与总耗时，区分失败、超时、取消和合法空结果；副作用请求使用幂等标识，结果未知先查原任务。站点要求登录或人工验证时如实提示，不吞掉错误伪造成功。

## 5. 构建与运行

Dockerfile 非空 UTF-8、最大 128 KiB；外部镜像使用名称与 sha256 摘要，允许工具选择基础镜像并在构建时安装浏览器、字体及系统包。业务 npm 依赖保持 package-lock 和官方摘要验证，额外安装明确精确版本、来源及完整性证明，不在源码或镜像中加入凭据。

保留 `AS build`，在 `/app` 提供 Node/npm、源码、开发依赖与可写构建目录；生产依赖裁剪放到后续阶段。平台独立检查容器执行 check/test/build，通过后再构建最终镜像；检查阶段通过不等于最终裁剪镜像的业务可用。

平台控制 Docker endpoint、网络、参数、隔离和超时，不提供宿主命令、挂载或特权。禁止隐式 VOLUME、ONBUILD、动态/未锁定外部 FROM、host 网络、insecure sandbox 和设备请求；syntax 省略或使用按摘要锁定的官方 docker/dockerfile。高级语法还需目标引擎支持。

| 运行档位 | 内存 / CPU | PIDs | /tmp / shm |
| --- | --- | --- | --- |
| standard（默认） | 256 MiB / 0.5 | 128 | 32 / 64 MiB |
| medium | 512 MiB / 1 | 192 | 64 / 64 MiB |
| large | 1 GiB / 2 | 256 | 128 / 128 MiB |

用 `resources: { profile: "medium" }` 选择平台实际开放档位；不是任意资源数值。构建/独立检查上限为 1 GiB、1 CPU，独立检查 256 PIDs。运行使用非 root、只读根目录、受限临时目录与无额外 swap；平台按更新时新旧版本重叠容量准入，档位可用不等于总容量足够。

浏览器和其他执行程序在最终镜像内运行，不在启动或任务期间下载二进制；使用经验证的沙箱，不能通过默认关闭沙箱、挂载 Docker socket 或放宽宿主策略解决问题。CPU、架构、libc、WASM 特性、字体、目标出口和真实资源峰值需按实际环境验证，本地预览不能模拟这些。

## 6. 发布、检查与升级

工具清单保持 schemaVersion 1、template ts-web、name、description、config、secrets、capabilities；当前无状态工具为 database/files 均 false，保留型声明不代表持久能力可用。具体 Schema 由助手与检查器校验，不手写平台来源锁和摘要。

助手 `check --run` 执行 11 项：声明、配置分类、Dockerfile、版本锁、结构、源码、依赖安装、check、test、build、平台预览。最后一项运行项目 `verify:platform`，应验证真实业务；检查器不自动知道业务应输出什么。

发布使用原助手身份和绑定，配置修订、源码与资源声明在受理时封存；候选健康后才切换，失败保留原服务。配置激活、回滚和恢复保持对应镜像与资源，重新启动仍经过准入；镜像回滚不恢复业务数据或本地源码。下线、恢复与删除均校验工具所有者，删除按助手明确确认对象。

升级按 [升级说明](规范升级说明v0.1.15.md)，新规范不自动迁移已有工具。平台能力、构建记录、最终镜像业务和实际浏览器操作分别验证；未运行目标用例记为 notRun，不把本机通过写成服务器已验收。

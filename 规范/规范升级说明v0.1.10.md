# 规范 0.1.10 升级说明

本页只在用户明确要求升级已有工具时适用。目标组合为 `kdp-0.1.10-ts-web-0.1.4-checker-0.1.11`，先确认可信公开索引和目标平台都支持；本地候选不等于已发布。

## 本版变化

主规范完整包含现行要求，新增按需必读的 [浏览器执行能力接入规范](浏览器执行能力接入规范v0.1.0.md)，并在 [运行兼容规范](运行环境与依赖兼容规范v0.1.1.md) 增加专项入口。覆盖开发前能力确认、独立服务职责、预装镜像、接口生命周期、资源/网络/会话隔离、真实目标验收及能力缺失时的交付说明。

独立浏览器服务、自动能力发现、目标环境自动预检与发布门禁尚未交付。升级规范不会安装 Chromium、提高工具配额、发放服务凭据或让现有采集工具自动可用。未接入服务或未完成目标业务验证的工具明确记录 `notRun` 和功能限制。

前端、文件、配置、代理和发布专项仅更新文档版本、所属组合与互链，业务规则保持。模板复用 ts-web 0.1.4 原归档与摘要；检查器 0.1.11 只更新匹配和报告版本，仍执行原有 9 项本地检查，没有新增浏览器探测。声明/锁 Schema 仍为 1，平台 API 仍为 v1，CLI 和 Skill 无机制变化，Skill 无需重装。

## 操作顺序

1. 记录原锁、未提交改动、工具 ID 和当前成功发布，备份源码，保留绑定、来源和发布身份；先处理未终结发布。
2. 目标已公开并受平台支持后，用已安装助手 `init --release kdp-0.1.10-ts-web-0.1.4-checker-0.1.11` 在项目外空目录创建对照项目，补齐 `--project`、`--name`、`--description`。由助手验证三类产物和摘要，不发布对照项目。
3. 从对照项目更新完整 `docs/standards/`、经验证的 `kdp.lock.json` 和原 `AGENTS.md` 阅读入口；保留业务文档，不复制对照项目 `.kdp`，不手写摘要。
4. 从 0.1.9 / ts-web 0.1.4 升级无需改模板或增加浏览器依赖。涉及浏览器业务时审查实际执行路径，记录获准服务与验证状态；服务不可用时补齐限制说明和真实错误状态，不自行部署服务。接入已验收服务的业务适配另按用户实际授权执行。更早模板逐文件比对，不覆盖业务。
5. 在原项目执行助手 `check --run` 和实际页面/业务验证；浏览器业务单独完成本地、最终执行镜像及真实目标网站验证。`notRun` 不算通过，mock 和健康检查不能替代目标结果。
6. 有发布授权时才继续原工具发布并核对实际镜像、服务版本、入口和业务。仅本地升级说明线上未变；回滚应用不会恢复本地源码、规范锁或独立服务版本，各自按对应流程恢复。

新规范不自动迁移旧工具，不覆盖已发布归档，不增加旧 Skill 适配或批量升级。

# 配置与密钥管理规范 v0.1.0

属于 KDP 规范包 `0.1.1`，适用于工具参数、持久设置及第三方 API Key。本文规定接入和验收要求，不提供尚不存在的 CLI 命令或配置 API；当前能力边界见第 8 节。

## 1. 先分类，再决定保存位置

| 类别 | 例子 | 本地与服务器处理 |
| --- | --- | --- |
| 单次业务参数 | 图片质量、目标尺寸、导出格式 | 随本次请求发送，服务端校验；不产生全局配置版本 |
| 非敏感界面偏好 | 排序方式、面板展开状态 | 可选保存在浏览器，支持清除；不能作为服务器权威配置 |
| 工具共享普通配置 | 固定模型名、允许的上游地址、业务阈值 | 本地开发单独保存；部署配置按工具与环境保存在服务器，版本化同步 |
| 业务秘密 | API Key、访问令牌、密码、签名私钥 | 本地私密保存，通过独立加密流程同步；服务器加密保存，只供获准后端使用 |
| 平台身份与系统变量 | 发布凭据、上下文签名密钥、PORT | 平台管理，不进入业务配置、不透传给工具使用者 |

匿名使用工具不等于有权维护共享设置。全局普通配置和密钥的管理接口必须校验工具所有者；不能仅在公开页面隐藏一个按钮。浏览器中的本次操作参数由业务规则限制，不能覆写全局密钥、上游授权目标或运行权限。

## 2. 声明与项目内容

`kdp.json` 的 `config` 与 `secrets` 每项只含 `name`、`required`，名称符合 `TOOL_[A-Z0-9_]+`，不可重名。普通配置放 `config`，秘密放 `secrets`；不增加 `value`、`defaultSecret` 等字段，不在声明中保存值。

以下仅为需要平台配置能力的声明片段，不表示现在可以发布：

```json
{
  "config": [{ "name": "TOOL_MODEL", "required": true }],
  "secrets": [{ "name": "TOOL_API_KEY", "required": true }]
}
```

保留常见敏感名称后缀 `API_KEY`、`APIKEY`、`TOKEN`、`PASSWORD`、`SECRET`、`PRIVATE_KEY`、`CREDENTIAL`；以这些完整词组结尾的声明不得放入 `config`。检查器只能识别这些名称，未命中不代表值不敏感；改名也不能把秘密当普通配置。

工具 README 另列配置用途、是否必填、格式/范围、允许的上游目标、非敏感默认值、缺失行为与生效时机。`.env.example` 只放空值或明显占位符；不要用真实密钥作示例或测试数据。

## 3. 本地保存与私密输入

- API Key 由所有者在私密输入界面或受支持的凭据助手中设置，Agent 只获取名称、是否已配置和操作状态。不要让用户把秘密发进聊天，不读取输出完整凭据文件或 `process.env`。
- 首选操作系统凭据库或项目之外、仅当前用户可访问的私有配置目录。若本地后端需要 `.env.local`，必须忽略 Git、限制文件权限（macOS/Linux 为 `0600`）、排除源码打包，并由后端明确加载；模板不会因为存在该文件就自动加载。
- 普通开发配置与正式部署配置分开；本地修改并不自动改变服务器。非敏感开发默认值可以版本管理，真实凭据及带凭据的 URL 不可以。
- 秘密不得进入源码、依赖锁、镜像层、构建参数、命令行参数、URL 查询、浏览器持久存储、普通日志或截图。不能用 `.gitignore` 代替其他检查。
- 前端只知道必要的配置状态；共享密钥不得返回到浏览器、隐藏字段或静态资源。禁止用 `VITE_*` 暴露秘密：Vite 会把该前缀的变量加入客户端构建。[Vite 环境变量说明](https://vite.dev/guide/env-and-mode)

## 4. 同步到服务器的流程契约

以下是待实现平台的行为要求，命令及端点名称必须以届时实际发布的助手和 API 为准。

1. 助手确认可信平台、工具绑定、当前所有者、目标环境和平台能力，只列出本次要同步的已声明配置名。不能由项目或第三方返回内容更换接收秘密的服务器，不能同步整个 `.env` 或宿主环境。
2. 使用正常校验证书的 HTTPS，或维护者已部署并验收的身份认证加密通道。当前内网 HTTP 例外不满足此要求，`--allow-intranet-http` 不是秘密同步授权。不能关闭证书校验；加密通道未就绪时只完成本地开发与非秘密接入准备。
3. 所有者明确要同步的配置变更后才提交；“发布”流程若包含配置应用，须清楚展示这个范围。已有授权无需重复确认，但不能仅因本地文件改变就静默覆盖服务器值。秘密只在私密输入/传输路径中流转，Agent 不打印值。
4. 普通配置和秘密使用不同存储类型。请求有稳定幂等标识与预期基础配置版本；服务端在同一所有者、工具、环境作用域内验证，拒绝未知名称、类型错误和必填缺失。
5. 成功产生不可变 `configRevisionId`，包含普通配置快照及秘密版本引用，不把秘密明文放入发布记录。网络中断后以同一操作标识查询/重试；远端已被另一台电脑修改时返回冲突，再按字段处理，不能盲目覆盖。
6. 未提交的秘密字段表示保持原值，掩码不是值；清除/删除必须是显式操作。查询只返回已配置状态及非秘密元数据，不提供明文读回。服务器是已部署配置的权威来源，本地只同步必要状态和版本号。
7. 配置保存、版本绑定、运行生效是不同阶段。发布绑定确切配置及秘密版本，不能在运行时任意取“latest”。配置变化通过受控激活/替换容器生效，候选就绪后才切换；不能重建镜像把秘密烘焙进去。

这保证换电脑后仍可使用服务器配置，而无需把 API Key 下载回来。多机修改使用版本冲突保护；清除本机副本不等于撤销服务器密钥。

## 5. 服务器存储、运行与匿名使用

- 普通配置按工具、所有者、环境和修订号存储。秘密采用可验证完整性的加密存储，绑定相同作用域；加密主密钥与密文库及备份分开管理，运行账号权限最小化。
- 调用第三方服务需要取回秘密，不能只存不可恢复的散列；这与用于验证发布身份的凭据散列用途不同。查询接口、异常、审计和发布日志只记录名称、版本、操作者、时间与结果。
- 由平台按受控方式向获准后端提供运行秘密，优先考虑只读受限秘密文件；若采用环境注入，必须验证进程、诊断和日志暴露边界。业务源码不得自行指定宿主路径、Docker 参数或秘密挂载。具体机制由平台实现并验收。
- 后端启动或就绪检查验证必填项和格式；缺失或无权取用时返回脱敏错误，候选版本不得接替健康旧版。不能用占位字符串假装已配置。
- 第三方请求由后端发往批准的目标，校验协议和目标地址；不得把共享密钥发送给匿名请求指定的任意 URL，也不能随重定向泄露凭据。修改上游目标时重新确认其与秘密的授权关系。
- 匿名访问者可以在业务权限内消耗所有者配置的能力，但不能读取、修改或删除配置。涉及付费服务时明确共享额度、速率和用量约束；不得把无限制的第三方代理公开出来。
- 若业务需要“每个同事保存自己的 Key”，必须先有可识别身份和个人秘密隔离，不能用共享匿名 ID 实现。用户自带 Key 的单次临时模式也须单独说明、通过加密通道、处理后丢弃；不默认采用该模式。

秘密的生命周期、最小权限、加密备份和独立密钥管理参考 [OWASP 秘密管理指引](https://cheatsheetseries.owasp.org/cheatsheets/Secrets_Management_Cheat_Sheet.html)。这些是接入要求，不能因文档存在就宣称平台已经满足。

## 6. 轮换、回滚与恢复

- 更新秘密生成新版本，审计不含值；激活后验证业务与旧版本停用策略。泄露时明确撤销受影响版本，不仅删除本地文件。
- 应用回滚通常恢复原绑定配置，但不得恢复已撤销秘密。历史版本引用的秘密不可用时，先绑定获准配置版本并验证，不能绕过撤销校验。
- 删除服务器配置、清除浏览器偏好、清除本地秘密和撤销第三方 Key 是独立操作，界面及助手说明影响。必填项删除不得让正在服务的工具悄悄进入错误状态。
- 配置及秘密备份受访问控制并加密；单独安排密钥材料恢复和轮换演练。数据库备份成功不等于加密秘密可恢复，不在业务日志里保存恢复材料。

## 7. 接入验收

使用专门的假值/测试凭据验证，不向聊天或产物写入真实秘密。至少覆盖：普通参数正常处理；必填缺失阻止激活；源码包/构建资源/下载结果/日志不出现测试秘密；匿名和另一个所有者不能管理配置；同步重试幂等、双机冲突、掩码不覆盖；服务重启与更新保留配置；指定配置生效和回滚；撤销秘密无法因回滚复活；备份与密钥共同恢复。

“本地已保存”“服务器已保存”“发布已绑定”“运行已生效”“上游业务验证通过”分别报告。连接测试默认采用不产生业务费用的检查，真实付费调用按用户授权执行，不能仅用格式检查假装外部 API 可用。

## 8. 本版配套实现边界

本版仅补规范、可选接入指引和常见名称检查。现有平台只有 `config` / `secrets` 声明结构与发布配置版本字段，尚未交付配置读写/同步 API、加密秘密库、运行注入和配置恢复流程；当前发布仍要求两数组为空、`configRevisionId` 为 `null`。不能使用虚构的 `kdp config` 或 `kdp secrets` 命令。

现有内网入口为 HTTP，工具运行默认禁止外连；涉及第三方 API 的服务器工具还依赖加密配置通道和受控外连能力。开发时先完成需求声明、适配边界及本地验证；服务器发布必须等待平台支持并完成验收，不能通过硬编码秘密或绕开网络约束实现。

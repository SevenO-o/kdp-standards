# 发布接口规范 v0.1

日期：2026-09-10 · 状态：v0.1 详细规范已获用户确认，本文路径、字段及状态机作为实现基线；现已进入开发阶段，实际进度与可用范围见仓库 README。第 8 节明确列出的环境参数和未决项在实施准备中落实。

上位方案见 [规范与服务器实施计划](../规范与服务器实施计划.md)。源码内的 `kdp.json`、`kdp.lock.json` 遵循 [工具开发规范](./工具开发规范v0.1.md)，本页不另建一套声明格式。首期发布对象为一个工具、一个生产环境；设备授权与凭证取得复用上位方案第 6 节，不假定飞书提供设备授权。

## 1. 请求和授权

- 全部接口使用公司配置的 HTTPS 地址及 `/api/v1` 前缀；路径中的 ID 均为不透明字符串，JSON 字段使用 camelCase，时间持久化为 UTC，接口使用带时区的 RFC 3339 字符串。
- 发布助手通过 `Authorization: Bearer …` 发送平台个人凭证，不把凭证放在 URL、源码包、命令行参数或模型输出中。此传输方式参照 [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html)；本平台凭证生命周期由自己的授权记录管理。
- 每次请求，包括上传、日志和幂等重放，检查账号状态、凭证、授权范围及资源归属。未知资源和他人资源统一返回 `404 RESOURCE_NOT_FOUND`，不能借编号查询确认他人的资源。依据见 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。
- 首期操作范围为 `tools:read`（本人登记信息）、`tools:write`（登记）、`releases:write`（上传、发布、回滚）、`releases:read`（能力、状态、历史、日志）；权限范围不能替代归属检查。
- 成功使用真实 HTTP 状态及 `{ "data": ..., "meta": ... }`，`meta` 可省略。错误固定为 `{ "error": { "code": "...", "message": "...", "requestId": "..." } }`；不返回堆栈、凭证、宿主机路径和私人正文。
- 所有 POST 必须带 `Idempotency-Key`。助手在第一次请求前保存随机键；同一用户、方法和路径下，同键同请求返回既有结果，同键不同请求返回 `409 IDEMPOTENCY_CONFLICT`。服务端记录与资源创建在同一事务内完成；鉴权失败不能凭幂等缓存返回资源。

## 2. 最小接口

以下路径均省略 `/api/v1`。`releaseId` 同时标识不可变发布记录与其执行任务，无需另一组任务 ID。

| 方法与路径 | 请求 | 成功及含义 |
| --- | --- | --- |
| `GET /publishing/capabilities` | 无 | `200`：支持的套件版本、包格式、上传/解包/文件数限制、上传有效期、幂等保留期及轮询间隔 |
| `POST /tools` | `name`、`description` | `201`：`toolId`、`ownerUserId`、`currentReleaseId: null`；owner 由服务端写入 |
| `GET /tools` | 可选 `cursor`、`limit` | `200`：本人 `items` 及 `meta.nextCursor`，用于重连或本地绑定丢失时恢复 |
| `GET /tools/{toolId}` | 无 | `200`：本人登记信息、`currentReleaseId`、当前访问地址和批准配置版本的元信息 |
| `POST /tools/{toolId}/releases` | `sourceSha256`、`sourceSizeBytes`、`configRevisionId`、`expectedCurrentReleaseId` | `201`：创建 `awaitingSource` 记录，返回 `releaseId`、`uploadExpiresAt`；此时不构建 |
| `PUT /releases/{releaseId}/source` | `Content-Type: application/gzip`；请求体为 tar.gz 原始字节 | `200`：完整收包、实测摘要/大小及 `sourceVerified: true`；不完整收包不成功 |
| `POST /releases/{releaseId}/submit` | 空 JSON 对象 | `202`：原子封存源码、检查前置条件并进入 `queued`；重复提交返回同一记录 |
| `GET /releases/{releaseId}` | 无 | `200`：当前状态、阶段、时间、脱敏失败原因、镜像/配置版本及访问地址 |
| `GET /tools/{toolId}/releases` | 可选 `cursor`、`limit` | `200`：本工具版本 `items` 及 `meta.nextCursor`；状态不等同于当前在用版本 |
| `GET /releases/{releaseId}/logs` | 可选 `cursor`、`limit` | `200`：有序 `items`，每项含 `sequence`、`timestamp`、`level`、`message`；`meta.nextCursor`、`meta.hasMore` |
| `POST /tools/{toolId}/rollbacks` | `targetReleaseId`、`expectedCurrentReleaseId` | `202`：创建 `kind: rollback` 的新发布记录，直接进入 `queued`，不重新上传或构建 |

capabilities 至少包含 `supportedPackageReleases`、`archiveFormats`、`maxSourceBytes`、`maxExpandedBytes`、`maxFileCount`、`maxPageSize`、`uploadTtlSeconds`、`idempotencyRetentionSeconds`、`logRetentionDays`、`pollAfterSeconds`；实际数值待环境验证。分页 `limit` 默认 20，最大为 capabilities 的 `maxPageSize`（20—100）；越界返回 `400 INVALID_REQUEST`。过期日志游标返回 `410 LOG_CURSOR_EXPIRED`，助手明确提示日志不完整。配置元信息只包含版本 ID、配置项名称及就绪状态，不包含真实值。首期无配置工具提交 `configRevisionId: null`；有配置工具引用服务端已批准的不可变配置版本，不存在或不可见的 `configRevisionId` 统一返回 `404 RESOURCE_NOT_FOUND`。配置录入和密钥轮换通过独立受控流程完成，具体管理接口另行设计。

所有接口拒绝未声明的请求字段，返回 `400 INVALID_REQUEST`；登记不能提交 `ownerUserId` 或服务器命令。`name`、`description` 使用 [工具开发规范第 3 节](./工具开发规范v0.1.md#3-工具声明-kdpjson) 的类型与长度约束。工具名称只是显示名称，不是归属或路由依据。助手在本地 `.kdp/binding.json` 中保存平台绑定与返回的 `toolId`，此文件不保存凭证且不随源码上传；包内存在该文件时返回 `422 SOURCE_INVALID`。目标工具只由已认证请求与平台记录确定。

本地 `kdp.json` 不表示服务器已登记。有绑定时助手先 GET 验证；404 后不能自动新建替代。已明确为新工具的首次发布可以登记，登记请求的幂等键在发送前持久保存；响应丢失时以原键恢复结果。复制项目或绑定遗失时，由用户指定已有工具或明确作为新工具发布，不能仅按展示名称自动绑定。

`supportedPackageReleases` 每项固定包含 `standardVersion`、`platformApiVersion`、`template: {id, version}`、`checkerVersion`、`manifestSchemaVersions` 和 `lockSchemaVersions`；后两项为允许的正整数格式版本数组，首版均为 `[1]`。助手和服务器按整项组合核对锁文件及声明，不能逐个版本独立匹配后任意混用。该列表由公司可信发布索引与当前服务器实际支持能力的交集产生；产物引用和摘要仍按可信索引核验。

## 3. 源码接收和不可变绑定

1. 助手先固定待发布快照，从同一快照运行检查、生成 tar.gz 并计算完整压缩字节的 SHA-256。`sourceSha256` 为 64 位小写十六进制；`sourceSizeBytes` 为实际压缩字节数。重试复用同一文件，重新打包属于新的发布请求。
2. 包含源码、依赖锁文件、`kdp.json`、`kdp.lock.json`；排除本地 `.kdp/binding.json`、真实 `.env`、凭证、个人输入/输出、数据库、依赖缓存和 Git 目录。未提交修改可以发布，但记录的是实际快照，不能谎称与某个 Git 提交完全一致。
3. 服务端先限制接收体积，流式写入不可执行暂存区；完整接收后独立计算摘要和大小，再验证解包上限。拒绝绝对路径、目录逃逸、重复路径、符号/硬链接、设备文件和危险归档条目；只接受常规文件及目录。不得边收包边构建。
4. 上传中断只留下有期限的暂存文件。首期不支持分片续传，助手重传原包；同一 release 的并发上传返回 `409 UPLOAD_IN_PROGRESS`。完整且匹配的包只保留一份，相同 PUT 可重复成功；不同字节、摘要或大小均拒绝。未提交记录超过 `uploadExpiresAt` 进入 `expired`，返回 `410 UPLOAD_EXPIRED`，清理暂存包且不启动构建。
5. `submit` 验证已收到合规包，读取两份 JSON 并检查可信来源的兼容矩阵及配置声明，再封存；目标工具从本发布记录及平台归属记录校验。`kdp.json.template` 必须与 `kdp.lock.json.template.id` 一致，锁定的规范、模板、检查器及 `platformApiVersion` 均须受支持。上传过期或封存后禁止替换源码；相同已验证上传的重放仍校验请求体摘要，只返回既有结果，不重写文件。
6. 服务端记录 `releaseId → toolId / ownerUserId / publisherUserId / authorizationGrantId / sourceSha256 / 套件锁定版本 / configRevisionId`。构建后追加实际 `imageDigest`、检查器及构建环境版本；这些事实由服务器生成，客户端不能自报覆盖。
7. 镜像按摘要使用；标签只用于显示。获准运行配置另有不可变 `runtimeConfigDigest`，摘要对象只包含运行参数及配置/密钥版本引用，不含秘密原文。源码、镜像、配置与执行记录一一关联，发布后禁止原地改值；密钥引用锁定具体版本，不能指向可变的“最新值”，只在运行阶段解析，生产密钥不进入构建环境。

## 4. 状态、并发与失败恢复

正常发布：`awaitingSource → queued → validating → building → deploying → verifying → succeeded`。成功 PUT 只设置 `sourceVerified`，`submit` 才推进到 `queued`。回滚跳过收包和构建，但仍需 `validating → deploying → verifying`。

- 终态为 `succeeded`、`failed`、`canceled`、`expired`。失败记录包含 `failureCode`、`failureMessage`、`recoveryState`；恢复中仍处于执行状态并持有锁，不得提前对外宣称已经回到旧版本。
- `recoveryState` 为 `notNeeded`、`oldVersionServing` 或 `manualRecoveryRequired`。错误状态必须同时返回实际 `currentReleaseId` 和 `serviceState`（`available`、`maintenance`、`unavailable`）；失败不等于旧服务一定可用。
- `expectedCurrentReleaseId` 是必填的并发前置条件，首次发布使用 `null`。受理发布及切换入口前均比较，变化时返回/记录 `CURRENT_RELEASE_CHANGED`，不自动覆盖别人的新版本或已有更新。
- 同一工具从 `submit`/回滚受理至终态只允许一个执行者；其他操作返回 `409 TOOL_BUSY`。平台总队列可跨工具排队；内部采用可恢复的独占租约和 fencing 标识，失去租约的旧执行者不能继续切换入口。
- 执行阶段保存检查点，服务重启后对照实际镜像、容器和路由恢复状态。不能仅因接口超时或 Worker 重启重复执行迁移；迁移须有独立版本记录和互斥控制，无法证明安全重试时转人工恢复。
- 新版本就绪后才切换入口；容量不足以新旧并存时采用明确维护窗口，不承诺零停机。成功记录保留历史，工具 `currentReleaseId` 指向当前版本；再次发布不会抹掉原有成功记录。
- 幂等记录保留期由 capabilities 明示，并覆盖正常排队/执行及客户端重试窗口。网络超时先查询已知资源，再以原键重试；超过保留期且无法确认结果时禁止助手自动创建新请求或重复迁移。

## 5. 凭证到期与权限撤销

请求凭证无效/到期返回 `401 TOKEN_INVALID` 或 `401 TOKEN_EXPIRED`；授权被撤销返回 `401 AUTHORIZATION_REVOKED`；账号停用返回 `403 ACCOUNT_DISABLED`，操作范围不足返回 `403 INSUFFICIENT_SCOPE`。401 同时返回适当的 `WWW-Authenticate: Bearer`，客户端据错误码处理，不把所有错误都当成网络问题。

已受理任务绑定服务端授权记录，不携带原始凭证。凭证自然到期不撤销该任务，但后续查询须重新认证；授权主动撤销、账号停用或归属不再满足时，未开始任务取消，执行中的任务在安全停止点终止后续操作。开始执行、迁移前及入口切换前重新校验授权状态。撤销不能抹去已发生的数据变更；保留真实阶段和恢复结果。

助手收到拒绝或撤销后停止自动认证重试；重新登录不能让已取消的发布偷偷恢复。内部执行器只接受平台持久化的结构化任务，不接受客户端 Shell 命令、宿主机路径、生产 Compose 或 Docker socket 请求。

## 6. 回滚与数据

回滚目标必须是本工具曾成功且仍保留镜像和获准配置的版本。平台创建新记录并绑定目标的镜像摘要及配置版本，保留 `targetReleaseId`；成功后 `currentReleaseId` 指向新回滚记录。引用不可用、密钥已撤销或运行配置不再获准时拒绝执行。

回滚应用不恢复数据库或文件。平台必须验证旧应用兼容当前数据库结构；未知或不兼容返回 `409 DATA_COMPATIBILITY_REQUIRED`。数据库/文件恢复是独立流程，需明确停机、备份点和可能的数据损失；本 API 不接受自动恢复数据的布尔开关。涉及迁移的发布先记录兼容性和恢复方案，无安全方案不进入部署。

## 7. JSON 流程正例

以下 ID、摘要与大小仅示意字段，不对应真实服务器或包。每个 POST 使用各自持久化的幂等键；示例无配置且无数据库迁移。

`POST /api/v1/tools`：

```json
{"name":"表格整理","description":"个人表格去重工具"}
```

响应 `201`：

```json
{"data":{"toolId":"tool_8c21","ownerUserId":"usr_7a32","currentReleaseId":null}}
```

`POST /api/v1/tools/tool_8c21/releases`：

```json
{"sourceSha256":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","sourceSizeBytes":245760,"configRevisionId":null,"expectedCurrentReleaseId":null}
```

响应 `201`：

```json
{"data":{"releaseId":"rel_91b4","kind":"publish","state":"awaitingSource","sourceVerified":false,"uploadExpiresAt":"2026-09-10T09:30:00Z"}}
```

助手 PUT 同一源码包并收到 `sourceVerified: true`，随后 POST `/api/v1/releases/rel_91b4/submit`，请求体 `{}`；受理返回 `202` 和 `queued`。助手按服务端建议间隔 GET 状态，只有 `succeeded` 才报告发布完成：

```json
{"data":{"releaseId":"rel_91b4","toolId":"tool_8c21","kind":"publish","state":"succeeded","imageDigest":"sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","configRevisionId":null,"runtimeConfigDigest":"sha256:abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789","currentReleaseId":"rel_91b4","serviceState":"available","toolUrl":"https://tool-8c21.tools.example.invalid/"}}
```

工具已有较新版本 `rel_b222` 时，POST `/api/v1/tools/tool_8c21/rollbacks`：

```json
{"targetReleaseId":"rel_91b4","expectedCurrentReleaseId":"rel_b222"}
```

发生跨用户访问时，响应 `404`：

```json
{"error":{"code":"RESOURCE_NOT_FOUND","message":"资源不存在或不可访问","requestId":"req_1e52"}}
```

## 8. 主要失败验收及未决项

| 场景 | 必须观察到的结果 |
| --- | --- |
| A 替换为 B 的工具、release、配置或回滚目标 ID | 拒绝且无源码、日志、版本或凭证泄露；伪造 owner 无效 |
| 上传断网、同包重传、同键不同内容、恶意归档、摘要不符 | 无提前构建；符合条件的重试复用记录；冲突拒绝，非法包返回 `422 SOURCE_INVALID` 或 `422 SOURCE_HASH_MISMATCH` |
| 体积/解包/配额超限或请求限流 | `413 SOURCE_TOO_LARGE`、`409 QUOTA_EXCEEDED` 或 `429 RATE_LIMITED`；提供适用的重试等待信息 |
| 模板版本不支持、依赖锁缺失、配置不全 | 拒绝或检查失败，有可处理错误码；服务器不能仅信任本地检查结果 |
| 凭证到期；排队时撤销；迁移期间停用 | 自然到期与撤销表现不同；不再受理未授权请求，已发生副作用与恢复状态准确记录 |
| 双客户端同时更新、超时重试、执行器重启 | 单工具互斥，幂等请求不重复发布/迁移，失效执行器不能切换路由 |
| 新版本未就绪、旧镜像删除、DB 不兼容 | 不误报成功；报告实际在用版本；回滚不会自动覆盖业务数据 |

实施前需收敛 capabilities 的限制和保留期、凭证有效期、受控配置管理流程、数据兼容性证明格式及实际独占执行机制；这些取决于服务器勘察和样板验证。本稿不提供尚不存在的可运行 CLI 命令或正式接口地址。

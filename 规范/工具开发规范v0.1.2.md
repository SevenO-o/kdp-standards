# 工具开发规范 v0.1.2

本版在 v0.1.1 上修订工具运行联网策略，其余要求继续继承。实际采用版本以项目锁定的完整组合为准，平台可用能力以已部署支持为准。

## 运行时联网

平台允许已发布工具主动访问网络，不设置目标域名白名单。工具后端可按业务需要解析域名、访问 HTTP/HTTPS API、上传参考文件及下载结果；实际连通仍受公司网络、目标服务和供应商区域策略影响。联网可用不代表任意第三方 API 均已验收。

工具仍运行在独立容器和每工具 bridge 中，端口通过平台代理提供访问；不要使用宿主网络、挂载 Docker socket 或修改平台运行参数。构建阶段继续使用平台固定的无网络构建流程，业务依赖沿用锁文件下载校验。

调用第三方接口应根据其实际文档设置输入限制、请求超时、并发及重试边界。用户可输入远端地址时，由业务后端校验请求目标并处理重定向，不能将任意 URL 获取能力直接变成访问内部服务的代理。不得将平台身份或其他工具的秘密发送给第三方。

## 与配置规范的关系

本版替代《配置与密钥管理规范 v0.1.0》中“工具运行默认禁止外连”和等待受控外连能力的历史状态说明。秘密的加密保存、同步、版本化激活及后端注入要求继续有效；是否已实现由平台实际支持决定。取消网络限制不等于已经提供 API Key 配置系统，不允许把真实 Key 写入前端或源码包。

## 旧工具兼容与迁移

联网属于服务器运行策略。维护者切换引擎并替换旧 DNS 容器后，旧工具可保留原业务源码、锁、发布记录和镜像取得联网能力；不要为此伪造新锁或自动重发工具。工具作者需要采用本版开发规范时，通过标准升级流程获取完整目标组合。未来发布及应用回滚使用服务器当前的网络策略，回滚应用镜像不会自动恢复旧的断网策略。

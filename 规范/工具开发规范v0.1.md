# KDP 工具开发规范 v0.1

日期：2026-09-10 · 状态：v0.1 详细规范已获用户确认，作为实现基线；现已进入开发阶段，实际进度与可用范围见仓库 README。实际依赖版本、产物和文中明确列出的环境事项按样板验证落实。

本规范从本次需求设计，适用于员工通过 KDP Skill 创建、开发和发布的个人 Web 工具。首期工具仅本人使用，输入、文件、任务和结果保持私有。设计背景见 [实施计划](../规范与服务器实施计划.md)，发布 API 见 [发布接口规范](./发布接口规范v0.1.md)。

## 1. 模板与运行形态

| 模板 ID | 前端 | 后端 | 适用范围 |
| --- | --- | --- | --- |
| `ts-web` | React + TypeScript + Vite + shadcn/ui | Node.js + TypeScript + Fastify | 默认选项，普通表单、查询及处理工具 |
| `python-web` | 同上 | Python + FastAPI | 业务依赖 Python 库时选用 |

普通工具以一个镜像、一个 HTTP 服务交付：构建后的前端静态文件随后端服务提供，前端与本工具 API 同源。运行时、包管理器和依赖版本锁定在实际发布的模板中；模板版本必须经样板构建验证后进入公司支持列表，文档中的模板 ID 不代表已有可下载产物。

v0.1 首个样板采用无状态 TypeScript 工具。Python 和持久化沿用本规范，但仅在对应模板及服务器能力已经验收并进入支持列表后允许发布。长任务 Worker 随业务需要单独增加受支持能力，不允许 Agent 自行增加部署服务。

## 2. 工具项目的固定结构

```text
工具项目/
  README.md                 # 运行、检查和业务说明
  AGENTS.md                 # 项目规则阅读入口，由 Skill 生成
  kdp.json                  # 工具声明，无账号和真实凭据
  kdp.lock.json             # 采用的规范、模板和检查器版本
  .kdp/binding.json         # 首次登记后生成的平台与工具绑定
  docs/standards/           # 锁定版本的规范快照
  web/                     # 前端页面与业务交互
  server/                  # 后端接口、业务逻辑、存储及外部调用
  contracts/               # 导出的 OpenAPI 与生成的前端类型
  tests/                   # 适用的业务与接入测试
```

模板还提供依赖锁文件、受控构建配置、无真实密钥的配置示例及标准开发入口。目录角色一致，内部业务文件按实际功能组织，不强制复杂分层。

`binding.json` 只记录公司平台标识与平台分配的工具 ID，不能存储凭证或决定所有者。平台地址由公司安装配置解析；项目不得通过修改绑定把发布凭证发送到其他服务器。该绑定不随源码包上传，服务端从已认证请求确定目标工具。

`kdp.json` 标识本地项目，不证明服务器已登记。有绑定时，发布助手先查询并验证对应工具；绑定指向不可访问工具时不自动新建替代。由本次创建流程产生的未登记项目，在首次收到发布指令后可以自动登记；助手在请求前持久保存幂等键，成功后保存平台返回的工具 ID。对来源不明、复制而来或丢失绑定的项目，不能按名称自动认领或无条件新建，需明确是恢复指定工具还是作为新工具发布。

## 3. 工具声明 kdp.json

JSON 根对象仅接受下表字段；未知字段返回声明校验错误，不能静默解释为新平台能力。

| 字段 | 类型及规则 |
| --- | --- |
| `schemaVersion` | 整数，v0.1 取 `1`，表示声明格式版本 |
| `name` | 非空字符串，去除首尾空白后 1—64 个 Unicode 码点；展示名称，不是身份主键 |
| `description` | 非空字符串，最多 240 个 Unicode 码点 |
| `template` | `ts-web` 或 `python-web`；必须与版本锁中的模板 ID 一致 |
| `capabilities` | 对象，必含布尔值 `database` 和 `files`；仅申请需求，实际是否提供由平台决定 |
| `config` | 配置声明数组，每项仅含 `name` 和布尔值 `required`，不含运行时真实值 |
| `secrets` | 密钥声明数组，每项仅含 `name` 和布尔值 `required`，不含真实密钥 |
| `retentionDays` | 任一持久化能力开启时必填正整数，否则省略；表示业务数据保存天数，受平台允许范围限制 |

`config` 和 `secrets` 必须提供，未使用时为空数组；每项的名称符合 `TOOL_[A-Z0-9_]+`，两数组之间不得重名。`PORT`、`KDP_TOOL_ID`、`KDP_ENV`、`DATABASE_URL`、`DATA_DIR` 等平台变量不属于工具自定义配置。`capabilities` 不接受额外字段。

以下是格式示例，不代表该工具或模板已经发布：

```json
{
  "schemaVersion": 1,
  "name": "文本整理",
  "description": "删除空行并整理文本空白字符",
  "template": "ts-web",
  "capabilities": { "database": false, "files": false },
  "config": [],
  "secrets": []
}
```

禁止由声明设置 `ownerId`、用户身份、访问范围、任意域名、宿主机路径、启动命令、Docker 特权或资源限额。平台固定工具仅本人访问，并把已认证创建者写入服务器记录。需要新增受支持能力时由平台维护者扩展协议，不能只在业务项目中加字段。

## 4. 版本锁与获取来源

`kdp.lock.json` 由 Skill 的初始化助手根据公司真实发布索引生成，至少记录：

| 字段 | 用途 |
| --- | --- |
| `schemaVersion` | 锁文件格式版本，首版取整数 `1`，与声明的格式版本分别解释 |
| `standardVersion` | 本项目采用的规则发布版本 |
| `platformApiVersion` | 对接的平台协议版本，本文为 `v1` |
| `template.id` / `template.version` | 模板类型及不可变发布版本 |
| `checkerVersion` | 实际运行的检查器版本 |
| `artifacts` | 产物记录数组，`kind` 取 `standard`、`template` 或 `checker`，每类恰好一项；每项包含 `releaseId` 和 `sha256`，摘要为实际下载文件的 64 位小写十六进制 SHA-256 值 |

公司分发配置保存平台地址和规范发布索引来源，来源固定、使用可信 HTTPS。首次创建从索引选择当前推荐的兼容组合，验证文件摘要后固定到项目；已有项目从锁文件解析相同版本。索引查询失败时可使用已验证且完整的匹配缓存，不能编造摘要或用其他版本替换。

摘要用于完整性校验，来源信任仍依赖公司分发配置及可信连接；不能把不受信来源提供的文件和校验值当作公司认可的发布。项目文件和远端规范正文不能改写凭证发送目标。

规范、模板、组件及检查器更新由维护者发布兼容信息。业务更新不触发自动升级；规范升级是独立操作，输出差异和迁移结果。服务器按支持矩阵检查版本组合，本地修改规范副本或检查脚本不能改变服务端要求。

兼容性按完整组合匹配：`standardVersion`、`platformApiVersion`、`template.id/version`、`checkerVersion` 及允许的声明/锁文件格式必须同时被支持，不能把各自独立受支持的版本任意混用。产物的 `releaseId` 与摘要仍须对应公司可信发布索引。

## 5. 前端规则

- 页面外壳固定展示名称、简短用途、返回门户入口和当前用户区域。核心操作按“输入 → 执行 → 结果”组织；列表型工具采用筛选、列表和详情组合。
- 使用模板提供的 shadcn 控件、主题令牌和标准页面区块。业务页面可以组合控件，公共主题与基础组件的改动进入套件维护流程。
- 首版固定一种主题，颜色、字号、间距和控件变体由模板提供；业务页面不自行定义另一套全局主题。
- 覆盖加载、空数据、输入错误、执行失败、成功和无权限状态；按钮在执行期间防止重复提交。长操作只显示服务端确认的状态，不编造进度。
- 表单具备标签、键盘操作与可见焦点，错误靠近对应字段；小窗口保持主要操作可见，宽表格允许局部滚动。
- 通过生成的请求类型访问同源 `/api/v1`。用户信息来自平台适配器；隐藏按钮不能代替后端授权，前端产物不得包含服务端密钥。

验收使用模板样板对照及实际浏览器操作。格式检查不能证明页面易用性，也不能替代业务结果验收。

## 6. 后端及数据规则

业务接口使用 `/api/v1`，字段名为 camelCase，资源 ID 为不透明字符串。时间保存为 UTC，接口使用带时区的 [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) 字符串；显示时按用户时区转换。列表采用 `limit`（默认 20、最大 100）和不透明 `cursor`，响应元数据提供可选 `nextCursor`。

成功 JSON 响应为 `{ "data": ... }`，需要分页时加 `meta`；失败为 `{ "error": { "code": "稳定错误码", "message": "可读说明", "requestId": "请求标识" } }`。同时使用真实 HTTP 状态：无效请求 400、未认证 401、权限不足 403、不可见资源 404、状态冲突 409、限流 429、服务故障 5xx。下载、204 和流式响应按其实际协议声明，不强套 JSON。

服务端 Schema 是接口类型的唯一来源，导出 [OpenAPI](https://spec.openapis.org/oas/v3.1.1.html) 并生成前端类型；前后端分别手写的重复类型不能作为契约。模板把两种后端的校验错误转换为统一结构，输入校验覆盖类型、长度、范围及文件限制。OpenAPI 与生成工具的实际支持版本随模板验证后锁定，不仅根据文档版本号宣称兼容。

服务端通过平台 SDK 获得已验证的 `userId`、`toolId` 和 `requestId`。SDK 校验可信来源、目标工具及有效期；客户端身份头由入口清除。具体身份传输封装在平台适配器内，业务代码不信任浏览器传入的所有者，也不直接依赖飞书标识。

业务记录、文件和任务保存工具及使用者归属，查询、下载、修改和删除均检查。单机可共用数据库服务，但每工具使用独立数据库权限和隔离文件卷；业务后端只通过获准的 `DATABASE_URL` 与 `DATA_DIR` 访问自己的资源。禁止把私人文件作为公开静态资源绕过检查。

外部调用设置超时和有限重试；收费或有副作用操作使用幂等机制，结果未知时先核对已有任务。密钥由平台配置，日志不记录凭证及原始业务内容。数据库变更通过迁移管理，说明旧版本兼容性；应用回滚与数据恢复分别处理。

## 7. 运行、检查和交付

| 项目 | 固定约定 |
| --- | --- |
| 监听 | 容器内监听 `0.0.0.0` 和环境变量 `PORT` 指定端口，生产运行构建产物 |
| 存活 | `GET /health/live` 只检查进程可响应，成功 200 |
| 就绪 | `GET /health/ready` 检查必需资源，成功 200、未就绪 503；不得调用收费服务 |
| 健康响应 | 最小 JSON 状态，不暴露配置和内部堆栈；探测入口仅平台内部可达 |
| 停止 | 收到 SIGTERM 后停止接收新请求，在模板配置的退出期限内结束；未完成操作按业务恢复规则处理 |
| 日志 | JSON 输出到 stdout/stderr，包含时间、级别、事件、工具、版本和请求标识；大小与留存由平台限制 |
| 持久化 | 容器临时磁盘仅用于可丢弃数据，镜像更新不删除业务卷与数据库 |
| 构建 | 使用公司受支持模板与锁文件；服务器再次检查，运行配置由发布器生成 |

模板提供开发、检查、测试和构建入口，命令及运行环境随实际模板发布；实际命令随可运行模板与发布助手交付。检查报告为结构化 JSON，至少包含规范与检查器版本，以及各项 `id`、`status`（`passed` / `failed` / `notRun`）、`message` 和必要证据位置。未执行不能计为通过。

交付材料包括源码快照、`kdp.json`、`kdp.lock.json`、依赖锁文件、接口契约、适用测试和业务说明。助手按模板允许清单打包，排除本地平台绑定、凭证、私人数据及依赖缓存；平台独立验证上传包。服务器必须重新生成或核验构建产物，不能只信任本地检查报告。

## 8. Skill 必须遵循的工作流

1. **识别任务**：创建、修改、检查、规范升级或发布；只讨论方案时不初始化项目。已有 `kdp.json` 按已有工具处理；非空未知目录不直接覆盖。
2. **获取规则**：使用公司启动配置解析版本，先读核心规则，再按模板及业务能力读取对应章节。缺少配置返回 `BOOTSTRAP_NOT_CONFIGURED`，缺少支持版本返回 `UNSUPPORTED_VERSION`。
3. **开发验证**：明确决定性输入输出，从标准模板完成页面与后端，执行适用检查和浏览器验证；失败后根据实际原因修复，不关闭检查规则。
4. **交付或发布**：创建请求交付可发布源码及检查结果；用户已要求发布时，调用本地发布助手衔接平台，已有授权不重复确认。
5. **报告事实**：区分开发完成、检查通过、上传完成、部署中和正式生效。上传失败或任务状态未知先查询，缺少证据不得声称上线。

本地发布助手独立处理授权、系统凭证存取和认证请求；其输出只含操作、状态、工具/发布 ID、版本、可公开的工具地址及稳定错误码。Skill 和普通日志不接收 Token、Cookie、完整环境变量或带凭证的 URL。凭证有效不代表可以操作他人工具，服务端逐次核验归属。

## 9. 进入实现前的具体交付与验收

按本设计制作实际模板、声明/锁文件 Schema、检查器和 Skill，并记录首批支持的 Agent 与运行环境。本页定义验收要求；实现状态、可执行命令与验证证据单独记录在仓库 README 和验收记录中，不能仅凭本页宣称开发套件已可用。

第一条验收路径为：安装 Skill → 一句话创建无状态工具 → 取得真实版本材料 → 完成本地开发与检查 → 通过受控发布接口部署 → 浏览器验证实际业务 → 更新同一工具并保留访问地址。

另外验证无效声明、版本不匹配、规范来源不可达、检查未执行、凭证过期和跨用户访问。持久化/Python 扩展分别取得重启、迁移、恢复与权限证据后进入支持列表。

# 文件上传与下载规范 v0.1.3

属于 KDP 规范包 `0.1.10`。以下“必须”是涉及该能力时的交付要求；自动检查边界见 [主规范](工具开发规范v0.1.10.md)。仅输入文件、仅输出文件的工具分别满足对应部分，不要求无关控件。

## 1. 交互与文件边界

- 由使用者选择本机文件，提供可用的文件选择入口；批量工具支持多选，拖放可选。说明格式、单文件大小、文件数及总量限制。
- 后端处理时采用“选择文件 → 上传 → 处理 → 结果 → 下载”；浏览器内处理也可采用，但必须说明文件是否离开本机，不能把服务器内存处理称作“本地处理”。
- 页面至少覆盖待选择、校验失败、上传中、处理中、成功和失败；支持的取消、重试及部分成功须有明确反馈。无法取得真实进度时显示阶段或忙碌状态，不能伪造百分比。
- 文件选择器不能赋予服务器读取使用者磁盘目录的能力。不得要求输入电脑绝对路径供服务器打开，不覆盖或删除使用者原文件。浏览器下载位置由浏览器和使用者决定。
- 处理参数改变后旧结果需标记过期；重复点击不能重复启动同一操作。大任务必须根据实际平台能力限时、限流，不能仅把前端超时无限延长。

## 2. 上传接口与校验

- 原始二进制上传优先使用 `multipart/form-data`；前端使用 `FormData`，不手写 boundary。无明确协议需要时不将文件编码为 JSON Base64。上传接口、参数和错误须列入生成契约。
- 工具页面通过同源相对地址访问，例如 `./api/v1/…`，同时适配 `/tools/<toolId>/` 的平台路径前缀。不得写死 localhost、容器端口或绕过平台访问容器。
- 前后端均检查大小、数量和格式；服务端重新校验，不能信任扩展名或浏览器 `Content-Type`。按业务检查签名、可解码性及内容类型，拒绝损坏、不支持和伪装输入。
- 除压缩前字节数外，必须考虑解码后内存、图片像素、归档展开量、输出大小、执行时间和并发。归档输入若不需要则拒绝；确需解包时限制文件数、展开总量并阻止路径穿越、绝对路径和链接条目。
- 每个工具根据真实运行配额选择限制；请求总量包括 multipart 开销，需小于网关限制。不存在对所有业务通用的图片数量或文件大小常数。限制同时写入 README 和页面，通过实际边界输入验证。
- 上传超限、格式错误、业务失败和服务繁忙使用项目统一错误结构与适当状态码；例如超限 `413`、不支持的内容类型 `415`、并发限制 `429`。不得返回堆栈、本机路径或原始文件内容。

文件安全校验应结合格式、实际内容、大小与解压后的资源消耗，单看扩展名不足以验证上传。[OWASP 文件上传指引](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)

## 3. 下载与批量结果

- 成功后提供真实下载操作。多个输出默认提供 ZIP，或根据产品需求提供明确的逐项下载。显示结果数量、大小，以及失败文件的可操作原因。
- 服务端文件响应设置正确 `Content-Type`、`Content-Disposition: attachment` 和有效下载文件名；涉及用户文件的响应设置 `Cache-Control: no-store`。同一接口失败时返回错误，不返回伪装成 ZIP 的 JSON。
- 前端先检查响应状态和类型，再创建下载；及时释放 Blob/Object URL。大文件超出当前内存传输能力时，先采用已经交付的流式或异步能力，不允许无上限缓存。
- 规范化输出名称，移除路径、控制字符和头部注入字符。中文名称使用兼容编码；同名输出须区分，ZIP 条目使用安全相对文件名，不包含服务器目录、源代码或配置。
- 批处理明确采用全部成功或允许部分成功的策略。部分失败须在页面及下载说明中可识别；全部失败不显示成功、不下载空成功包。ZIP 内报告只包含本次请求所需的脱敏元数据。

## 4. 临时存储、隔离与清理

- 默认只在本次任务期间保存输入和结果；只需内存处理时不落盘。落盘使用服务器分配的独立任务临时目录与随机内部名称，不以用户文件名拼接路径。
- 任务之间隔离，禁止共享“最近结果”文件或按全局用户名拼接结果目录。匿名内网使用者共享 `intranet-visitor`，该值不是个人身份，不可据此宣称数据私有。
- 直接随本次请求返回结果优先。若要分步上传、异步任务或单独下载链接，必须有已验收的任务访问凭据、不可猜测的高熵标识、短有效期和越权保护；仅有自增 ID 或工具 ID 不够。凭据不得写入公开日志。
- 成功、失败、取消和超时均清理本次临时文件；对崩溃遗留定义有限 TTL 和启动清理。内存型实现随请求释放资源，并验证取消会终止或有界结束处理。
- 只清理本工具管理的目录，不使用全局临时目录清空命令。临时文件不得进入源码包、镜像、普通日志或长期备份。
- 跨请求/跨重启保留文件、历史或任务属于持久能力，须申请并使用平台已交付的存储、访问隔离与保留策略。`capabilities.files: false` 只适用于不依赖持久保存的处理流程。

## 5. 交付验收

在实际目标入口完成“上传 → 处理 → 下载 → 打开结果”，仅 HTTP `200`、健康检查或下载链接存在不能算通过。至少覆盖：

1. 一份真实有效输入，核对处理内容及文件可以打开；图片检查格式、尺寸和预期透明度等业务特性。
2. 批量、同名、中文文件名、部分失败及全部失败（业务允许的分支）。
3. 超大小/超数量、伪装格式、损坏文件、解码资源上限及并发限制。
4. 取消、断连、超时、失败后重试；重复执行不出现上一次请求的文件。
5. 实际平台路径前缀下上传与 attachment 下载有效，错误响应不被保存成结果文件。
6. 在目标运行配额内验证峰值内存、处理时限和临时清理；未在服务器验证时只报告本地通过。

前端交互、内容质量和清理不能仅依靠当前检查器证明。README 记录实际限制、暂存位置、清理时机及验收范围；平台尚不支持的能力明确标为未接入。

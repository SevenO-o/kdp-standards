# 规范 0.1.8 升级说明

本页只在用户明确要求升级已有工具时适用。目标组合为 `kdp-0.1.8-ts-web-0.1.4-checker-0.1.9`，先确认可信公开索引和目标平台都支持；候选不可直接当作已发布组合。

## 本版变化

- 主规范完整合并当前规则，不再追溯 0.1 至 0.1.7。
- 前端、文件、配置、可选代理与发布接口各有独立、完整的当前文档；只按业务阅读专项。
- 将匿名访问、开放运行出口、默认后端环境注入、专用 HTTPS 和工具生命周期写成一致要求，删除已被替代的设计状态。
- 模板 ts-web 0.1.4 仅更新 README、可选能力说明及版本元数据，业务、主题和依赖与 0.1.3 相同；检查器 0.1.9 仅更新所匹配和报告的组合，不增加新的业务检查。声明/锁 Schema 仍为 1，平台 API 仍为 v1。

从规范 0.1.7 / 模板 0.1.3 / 检查器 0.1.8 升级时，无业务代码、主题或依赖变更要求。更新模板说明、规范快照、完整平台锁和项目规则入口后进入验证；不能只手写版本号。

## 操作顺序

1. 记录原锁、未提交改动、工具 ID 和当前成功发布；保存本地源码备份，保留原绑定、来源记录和发布身份。已有未终结发布先处理。
2. 用已安装助手 `init --release kdp-0.1.8-ts-web-0.1.4-checker-0.1.9` 在项目外的空目录创建对照项目，补齐 `--project`、`--name`、`--description` 参数。助手验证三类产物及摘要；不要发布对照项目。
3. 用对照项目的完整 `docs/standards/` 替换原规范副本，移除已被替代的旧正文；保留工具自身业务文档。复制经验证的完整 `kdp.lock.json`，更新原 `AGENTS.md` 的规范入口和组合，保留项目特定规则。
4. 0.1.7 基线只合并模板 README 与 `docs/可选能力接入.md` 的说明，不覆盖工具自有 README；业务包版本不必跟随模板编号，依赖锁无需改变；来自更早模板的工具，需另比对原模板、当前业务代码和目标模板，逐文件合并并验证，不覆盖业务或新增历史 Skill 兼容分支。
5. 在原工具执行助手 `check --run`，确认所有适用项通过，验证实际页面与业务；`notRun` 不计通过。仅本地升级时报告线上仍是原发布。
6. 有发布授权时向原工具发布并验证原链接和业务；失败保留真实状态。回滚应用不恢复本地锁或源码，需使用对应备份另行恢复；不要复制对照项目的 `.kdp` 或新建替代工具。

Skill 无客户端机制变化，不要求重装。新项目由推荐索引自动取得完整组合；旧工具不自动升级。所有旧归档保留，本次不增加旧客户端适配或批量迁移功能。

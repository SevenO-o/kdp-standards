# KDP 工具开发规范 v0.1.1

适用规范包：`standardVersion: 0.1.1`。本版补充文件处理与配置管理的开发要求，不改变声明和锁文件的 `schemaVersion: 1` 或平台 API `v1`。规范要求、检查器拦截和平台已实现能力分别说明，不能互相代替。

## 1. 继承与修订

沿用 [v0.1 基础规范](工具开发规范v0.1.md) 的目录、React / Vite / shadcn、Fastify、接口生成、错误结构、版本锁、安全打包和受控运行契约。本版对以下旧描述作明确修订：

- 工具使用范围由平台部署模式决定。当前内网模式允许匿名使用已发布工具；发布、更新、回滚及未来的配置管理仍验证工具所有者。共享的 `intranet-visitor` 上下文不代表一个可识别的员工，不能用于隔离每个人的私有历史或配置。开发模式继续执行原有私有访问检查。
- 内网模式可由维护者配置固定内网 IP 和 HTTP 来源；这不是加密传输。新增 API Key 等业务秘密的同步要求见配置专项规范，不能沿用 HTTP 例外传输秘密。
- `capabilities.files` 表示平台持久文件能力。浏览器上传、服务端临时处理后直接返回，不申请持久文件能力，仍可为 `false`。跨请求保存任务或结果不能借此绕过能力申请。
- 旧规范和发布接口文档中关于非空配置版本、存储、飞书等内容是设计契约，不表示当前平台已交付。Python、持久数据、配置同步和密钥注入须在对应能力实现并验收后使用。

工具仍必须验证每次发布独立的签名上下文，经网关访问，不向浏览器或业务服务转交平台发布凭据。内网匿名使用不放宽管理端所有权约束。

## 2. 按业务启用的开发要求

| 工具需求 | 必须遵循 | 无此需求时 |
| --- | --- | --- |
| 用户文件输入、导入 | [文件规范](文件上传与下载规范v0.1.0.md)：可操作的选择/上传入口、限制、状态与服务端校验 | 不强制增加上传控件 |
| 文件输出、导出 | 文件规范：真实文件下载、多结果的打包或明确逐项下载、失败处理 | 不强制增加下载控件 |
| 单次业务参数 | [配置规范](配置与密钥管理规范v0.1.0.md)：随请求传递和服务端校验 | 不引入配置系统 |
| 跨设备或重启后保留的工具设置 | 配置规范：普通配置声明、服务器保存、版本冲突和激活流程 | 不引入全局设置页 |
| API Key、令牌、密码等 | 配置规范：秘密声明、私密输入、独立同步、后端使用和轮换 | 不要求填写密钥 |

“预留能力”要求有需求的工具实现可使用的输入输出或接入流程，不要求每个模板放置空按钮、无效设置页或虚构接口。

## 3. 模板、Agent 与检查器的责任

- 模板提供通用结构和可选能力接入说明；工具作者按业务实现页面、接口与测试。接口改变后通过 `contracts` 生成契约并同步调用端。
- Agent 首先读取锁定规范和相应专项文档，核实平台支持，随后开发、检查和验证实际业务。缺少平台能力时记录缺口，可交付本地实现和待接入契约，不能在工具里另造宿主挂载、远程秘密文件或绕过发布限制。
- `checker 0.1.2` 对应 `standard 0.1.1 + ts-web 0.1.2`，检查声明、版本、目录、源码打包以及项目自身的依赖安装、类型、测试和构建，并检查常见密钥名称是否误放到 `config`。
- 上述命名检查仅覆盖配置专项规范列明的后缀，不能识别所有敏感信息；项目脚本也可被作者修改。检查通过不代表上传下载体验、密钥不泄露、配置同步或运行环境已经验收。
- 服务端继续独立检查支持组合、能力、归属、源码与依赖；没有声明在服务端实现的新拦截，不应报告成服务端强制保障。

## 4. 交付与迁移

工具 README 必须写明适用的专项规则、文件和参数限制、数据保存位置/期限、实际已支持功能及未接入项。验收证据只能记录元数据和脱敏结果，不记录输入文件内容或秘密值。

普通业务更新沿用原锁。采用本规范需从可信索引取得完整新组合，合并模板可选能力说明、更新规范快照及项目规则，并完成条件适用的业务验收。旧工具继续使用对应旧检查器；新规范不自动迁移旧代码或改变已有服务器配置。

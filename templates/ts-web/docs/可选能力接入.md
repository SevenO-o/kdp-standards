# 开发示例与模块入口

ts-web 0.1.6；按需参考。先读 `docs/standards/README.md` 指向的唯一框架约定。

## 文件上传与下载

使用 FilePicker 选择文件，将 FormData 交给公共模块，不手写 boundary：

```ts
import { requestDownload } from './lib/http';
const body = new FormData();
body.append('file', file);
const result = await requestDownload('images/compress', { method: 'POST', body }, {
  expectedTypes: ['image/png', 'image/jpeg', 'image/webp'],
  sourceBytes: file.size,
});
// result.outputBytes 是实际下载字节数，sourceBytes / savingsRatio 可能为 null。
const url = URL.createObjectURL(result.blob);
// 交给 DownloadButton；替换结果或组件卸载时 URL.revokeObjectURL(url)。
```

路径、字段和类型仅为示例，需要实现匹配的后端及生成契约；模板未预装压缩接口。ZIP 的下载体积不是其中图片体积之和。处理失败不会变成成功文件，业务仍需校验格式、像素、数量和临时文件清理。

## 配置

在 kdp.json 中声明 TOOL_ 名称，API Key 放 secrets，本地从环境读取，发布由助手同步；普通工具无需设置页。模板不自动读取 `.env.local`，采用该文件时在后端入口显式加载且保持源码打包排除。

## 浏览器、字体与其他依赖

在工具 Dockerfile 构建时安装，保留 build 阶段开发依赖，将必需文件留在最终镜像。按平台开放档位设置资源；不需要先建设独立浏览器服务。真实浏览器启动、目标网站和资源限制必须按业务验证，不能用 npm 安装成功代替。

## 本地验证

`npm run dev` 的 API 经过共享网关；`npm run build` 后可用 `npm run preview:platform` 操作生产页面。将 `scripts/verify-platform.ts` 的样例替换为本工具业务，并运行 `npm run verify:platform`。助手完整检查也会运行它。

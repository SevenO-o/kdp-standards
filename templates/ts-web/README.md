# 文本整理

前端采用 KUNPO 青蓝主题，默认浅色并支持记忆深色选择。公共组件与示例用法见 [组件说明](web/components/README.md)，主题入口为 `web/theme.css`。单栏、分栏、列表等结构按业务选择，不要求照搬文本整理样板。当前模板源码为 0.1.7；可用发布组合以可信索引和项目锁为准。

KDP TypeScript 工具样板：删除空行、去除行首尾空白、合并连续空白。支持中文、英文与 Unicode 文本，最多 100,000 字符；只处理空白和换行，不保存文本。

按需查看 [可选能力接入](docs/可选能力接入.md) 及初始化后下载的锁定规范。按需求实现上传下载或配置接入，不给所有工具增加空的设置页。

## 本地开发

需要 Node.js 24。本机开发验证使用 24.16.0；容器基础镜像固定为官方 Node.js 24.18.0 / Debian bookworm-slim 的真实仓库摘要（见 Dockerfile），当前容器验收平台为 arm64。

```sh
npm ci --ignore-scripts
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`。开发服务仅监听本机，页面显示“本地开发”；该身份不代表已登录公司平台。

```sh
npm run check
npm test
npm run build
npm run verify:platform
npm run preview:platform
```

最后一条以平台方式预览构建后的服务，入口 `http://127.0.0.1:5174/tools/local-tool/`；包含真实生产静态资源、签名上下文、路径前缀与平台相同的网关逻辑。页面输入“`  甲    乙`”与空行，整理后应得到“`甲 乙`”；修改规则或输入后旧结果标记过期，重新整理才可复制。

`server/schema.ts` 定义接口，`npm run contracts` 导出 `contracts/openapi.json` 并生成 `contracts/api.d.ts`，前端引用生成类型。不要分别手写相同的请求和响应类型。

## 发布和运行

通过 KDP Skill 与发布助手发布。初始化后由助手写入真实版本锁与规范快照，不手工填写摘要或所有者。发布配置和凭证不放入源码。

生产运行必须由平台提供 `KDP_ENV=production`、`KDP_TOOL_ID`、每工具独立的 `KDP_CONTEXT_SECRET`、`PORT`。容器非 root、监听 `0.0.0.0:$PORT`；业务请求与静态页面均验证平台签名上下文，只允许网关访问容器。`/health/live` 与 `/health/ready` 供平台内部探测。内网模式下平台签名上下文的 `userId=intranet-visitor` 表示匿名访客，不是发布者身份；页面显示“内网可用”。本地开发与所有者访问模式保留独立提示。

收到 SIGTERM 后，服务停止接受新请求并在 10 秒内退出。JSON 日志不记录正文和凭证。本样板不申请数据库或文件能力；增添持久化需要相应平台能力验收后再发布。

## 自定义构建与联网

平台使用项目根目录的 Dockerfile，不覆盖其内容。外部 FROM 按镜像摘要锁定；构建可联网，允许在镜像构建期间安装系统库、字体与浏览器。下载版本和来源须明确，禁止把真实凭据写入文件或镜像。

保留 `AS build` 阶段，在 `/app` 提供源码、Node/npm 与完整开发依赖。平台构建该阶段后另起受限容器，依次执行 `npm run check`、`npm test`、`npm run build`；任一步失败停止发布。生产依赖裁剪放到后续阶段，不从检查阶段删除开发依赖。最终镜像按平台非 root 用户、只读根目录和资源档位运行，监听 3000 并实现健康接口；不支持 VOLUME 隐式持久化。

运行时不得临时下载安装二进制。安装成功后仍需完成目标 CPU、镜像和核心业务验证，浏览器下载不等于 Pinterest 采集成功。当前为本地模板候选，目标服务器须已支持完整规范组合。

## 本地与服务器一致性

Vite API 与生产方式预览复用 `shared/tool-http.ts`；平台使用同一模块，维护者同步时校验字节一致。业务响应头、上限、超时及签名隔离不再仅在线上生效。平台仍负责真实所有权和容器运行隔离，本地预览不模拟目标 CPU、内存限制、持久服务或外网。

JSON、错误和文件请求集中在 `web/lib/http.ts`，文件大小取实际 Blob；缺失指标保留未知。`scripts/verify-platform.ts` 验当前文本业务的成功与失败，替换业务时同步修改断言；不得留无关样例报告通过。

## 文件传输

本地网关与平台共享 HTTP v2：普通接口请求/响应最多 8 MiB，文件双向流式传输，默认每次 256 MiB；超限或取消会停止上游。文件完成前不要显示下载成功。流式响应已发送后出错会断开下载，不能再改成 JSON 错误。

维护者可通过 `KDP_TOOL_FILE_MAX_BYTES`（字节，0 取消文件大小上限）、`KDP_TOOL_FILE_TIMEOUT_MS`（默认 300000）和 `KDP_TOOL_FILE_CONCURRENCY`（默认 4，每网关进程）配置。同一配置应用于本地网关与目标平台；本地可在启动命令前设置环境变量。平台真实值由已认证的 publishing/capabilities 接口提供。工具不能通过发布环境变量改变平台网关策略。

文件请求按 multipart/form-data、常见二进制 MIME 类型识别；成功文件响应按 MIME 或有效 attachment 识别，普通 JSON 始终保留 8 MiB。文件下载等待响应头默认 15 秒，开始传输后计文件超时；multipart/二进制上传从开始起计文件超时。长耗时生成应使用任务接口，结果就绪后再下载。

业务服务自己的文件解析器、大小和超时限制仍需匹配实际需求；大文件用流式解析/输出，避免 `toBuffer()`。前端公共下载模块仍通过 Blob 获取完整结果，大文件可使用普通浏览器附件下载；服务器流式转发不等于浏览器内存恒定。公共下载模块可通过 `timeoutMs` 匹配目标的文件超时。
